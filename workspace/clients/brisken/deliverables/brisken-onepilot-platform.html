The problem

Why does a treasurer's day become tab management?

Because the work is scattered across systems that do not talk to each other: SAP, two bank portals, a trading screen, market data, email and a spreadsheet.

So the numbers get re-keyed between them, and the day goes to moving data instead of using it. OnePilot puts the data in one governed place, so the day shifts back to using it: deciding, not re-typing.

What it is

OnePilot is Brisken's governed, no-code platform for running financial data in SAP. It is one surface where a user composes the apps and data their work needs, and permissioned AI agents do the repetitive work across all of it.

It is a framework in three layers: the framework IT sets up once, the spaces a user builds in plain language, and the agents that act within that user's permissions. TreasuryCentral is its first scoped edition, live on SAP.

TreasuryCentral is the one shipped edition of OnePilot, live on SAP today. It puts the treasurer's whole day on one surface: cash, FX, market data, trades, bank files and remittances, governed end to end.

Each task moves from a string of logins to one glance: cash reconciled overnight by exception, payment runs staged for four-eye release, the board pack drafted to your template.

The applications

BST is OnePilot's FX and trade-execution application, and the live flagship. It brings exposure, market data and execution onto one surface and logs every action back into SAP under four-eye control.

The Market Data Hub brings live market data into SAP in the context where it is used, so a rate sits next to the position it affects rather than in a separate terminal.

The Remittance Advice Gate has an agent read incoming remittances and structure them into SAP cash application, removing the manual re-keying. The agent prepares the entries; a person approves them.

OnePilot is not a fixed product; it is a framework in three layers. The framework is set up once; the spaces and the agents are yours, changed in plain language.

1
Brisken and IT, once

The framework

Connectivity, permissions, security and boundaries. Set up once, it makes the surface safe to build on and keeps every space inside the same governed perimeter.

2
You, continuously, in plain language

Your spaces

A canvas of widgets that pull in whatever you work with, from wherever you have access. Build as many as the work needs: a day's flow, a recurring job, an occasional task. No build queue, no IT ticket.

3
You direct; the framework constrains

The agents

AI agents see and act across everything in your spaces, strictly within your permissions. You set the rules and approve the exceptions; the agents do the busywork, by exception, underneath.

Composed, not coded

Integration moves from the IT ticket to a plain-language ask. Describe the space you want, for example "build me a morning cash space", and the widgets compose onto the canvas, each pulling live from a connected source: cash position, FX exposure, bank files, email and Teams approvals, the board pack, market data. The same surface builds a close space, a deal space, an operations space.

The framework constrains; the user directs. An agent carries the same access limits as the person it works for, with the controls a regulated finance team needs to standardize on it.
