# Apify Scraper Starter

Automatically starts LinkedIn scrapers when your lists are ready, with smart queue management to prevent overload.

## What This Does

When you create a new list in the List Building table and it's ready to be scraped, this automation:

1. Checks if there's capacity to run another scraper (max 4 at a time)
2. If there's space, it starts the LinkedIn scraper with your list's search URL
3. If all scrapers are busy, it queues your list and will try again later
4. Updates the list status so you can track progress

**Runs:** Automatically when triggered by the List Building Orchestrator (when a list status changes to "Scraper Started")

## How It Works

1. **Receives a trigger** - The List Building Orchestrator tells this automation which list is ready to scrape

2. **Checks availability** - Looks at how many scrapers are currently running. If 4 are already running, it queues your list instead of starting right away

3. **Gets LinkedIn credentials** - Retrieves the LinkedIn cookies from your configuration to access LinkedIn without triggering security alerts

4. **Starts the scraper** - Sends the list's search URL and settings to Apify to begin scraping LinkedIn profiles

5. **Updates your list** - Changes the status to "Scraper In Progress" and saves the scraper ID so you can track it

## What You'll See

When this automation runs successfully, you'll see:

### In Airtable

**If scraper started:**
- List status changes to **"Scraper In Progress"**
- Scraper ID field is populated (looks like "run123abc")
- You can click the Apify dashboard link to watch it run

**If queue is full:**
- List status changes to **"Scraper Queued"**
- The orchestrator will automatically retry when a slot opens up
- No action needed from you

### In the Dashboard

- Success notification in the logs
- Step-by-step details of what happened
- Number of scrapers currently running

### In Apify

If you want to see the actual scraping in action:
1. Go to [Apify Console](https://console.apify.com/actors/runs)
2. Look for runs with the ID shown in your Airtable list
3. Watch live progress as profiles are scraped

## Status Meanings

When you check your List Building table, you may see these statuses:

| Status | What It Means | What Happens Next |
|--------|---------------|-------------------|
| Scraper Started | Ready to be picked up by this automation | Automation runs immediately |
| Scraper In Progress | Scraper is actively running on Apify | Wait for completion (usually 10-30 min) |
| Scraper Queued | All scraper slots full, waiting for capacity | Automatically retries when space opens |
| Scraper Completed | Scraping finished successfully | Data is being processed (see A6.2) |

## Configuration

### LinkedIn Cookies

This automation uses LinkedIn cookies stored in your **Configs** table to access LinkedIn. You have three cookie accounts configured as backups:

- **Linkedin_cookie_a** - Primary account (tried first)
- **Linkedin_cookie_b** - Backup account (tried if primary fails)
- **Linkedin_cookie_c** - Additional backup (tried if both others fail)

The system automatically tries each account in order until it finds one that works.

### Queue Limit

**Maximum concurrent scrapers:** 4

This limit prevents overloading resources and ensures stable performance. If you need more capacity, contact your automation manager.

## Troubleshooting

### "No valid LinkedIn cookies found in config table"

**What this means:** The automation couldn't find working LinkedIn cookies in your Configs table.

**What to do:**
1. Check that your Configs table has at least one of these fields: `Linkedin_cookie_a`, `Linkedin_cookie_b`, or `Linkedin_cookie_c`
2. Verify the cookie value is properly formatted JSON (should look like `[{"name": "li_at", "value": "..."}]`)
3. The cookies may have expired - refresh them using Cookie-Editor extension in your browser

### "List stays in 'Scraper Queued' for a long time"

**What this means:** All 4 scraper slots are occupied and other scrapers are taking longer than expected.

**What to do:**
1. Check the [Apify Console](https://console.apify.com/actors/runs) to see which scrapers are running
2. If any are stuck, you can cancel them to free up slots
3. Your list will automatically start when space becomes available - no manual action needed

### "Scraper starts but immediately fails"

**What this means:** The scraper started but encountered an error, usually with the LinkedIn cookies or search URL.

**What to do:**
1. Verify your LinkedIn search URL is valid (should start with `https://www.linkedin.com/sales/search/`)
2. Check if LinkedIn cookies need refreshing (see troubleshooting above)
3. Check the dashboard logs for specific error details

### "List status doesn't change"

**What this means:** The automation may not have been triggered or encountered an error.

**What to do:**
1. Check the dashboard logs for this list's record ID
2. Verify the list status was set to "Scraper Started" (that's the trigger)
3. Check that the List URL and List Type fields are filled in

## Behind the Scenes

### Why Queue Management Matters

Running too many scrapers at once can:
- Slow down all scrapers due to resource limits
- Trigger rate limits on LinkedIn
- Increase costs on Apify

The 4-scraper limit ensures optimal performance and cost efficiency.

### How Cookies Work

LinkedIn uses cookies to verify you're logged in. The automation:
- Stores cookies securely in your Airtable Configs table
- Automatically rotates between backup accounts if one fails
- Uses browser-like settings to avoid detection

### Scraper Details

**Actor used:** curious_coder/linkedin-people-search-scraper (ID: `7Q2x4Chr5xNR5s4dP`)

**Settings:**
- Starts from page 1
- Waits 2-5 seconds between requests (looks more human)
- Uses Apify proxy to avoid IP blocks
- Respects max results limit if you set one
