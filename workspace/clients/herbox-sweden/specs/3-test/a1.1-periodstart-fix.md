# A1.1: PeriodStart Logic Fix

## Goal

**Problem:** The A1 Recurring Order workflow currently uses `PeriodEnd` to determine when contracts are due for order generation. Nils clarified that `PeriodStart` is the correct deciding factor — because `PeriodEnd = PeriodStart + InvoiceInterval`, so PeriodEnd represents the *next* period, not the current one.

**Solution:** Change the timing logic in the A1 n8n workflow to use `PeriodStart` as the trigger date instead of `PeriodEnd`.

**Business Value:** Correct order timing — orders are generated based on when the current subscription period actually starts, not the next period boundary.

## Context

From Nils (2026-02-17):
> "End period = start period + interval. So we always need to scan start period."

### What This Means

In Fortnox contracts:
- `PeriodStart` = start date of the current subscription period
- `PeriodEnd` = `PeriodStart + InvoiceInterval` (i.e. when the next period begins)
- The system should generate orders based on how close we are to the **next PeriodStart** (i.e. the upcoming period start), not the PeriodEnd

So the logic should be: **"Generate an order when `PeriodStart + InvoiceInterval` is within 30 days from today"** — which effectively means the same date as PeriodEnd, but conceptually framed around PeriodStart as the anchor.

> **Important:** Verify with Nils whether the threshold should remain 7 days or change to 30 days. The current workflow uses 7 days. His email mentioned "coming in less than 30 days" for the dashboard display, but the generation threshold may differ.

## Current State

**Workflow:** A1 Recurring Order Automation (ID: `qJHgvXLKFdCBja1o`, currently INACTIVE)

### Nodes That Need Changes

#### 1. "Calculate Order Timing1" (Code node)

Current logic (from A1 spec):
```
daysUntilEnd = PeriodEnd - today
Filter: daysUntilEnd <= 7 && daysUntilEnd >= 0
```

**Change to:**
```
nextPeriodStart = PeriodStart + InvoiceInterval (months)
daysUntilNextPeriod = nextPeriodStart - today
Filter: daysUntilNextPeriod <= 7 && daysUntilNextPeriod >= 0
```

> Note: `PeriodStart + InvoiceInterval` = `PeriodEnd` numerically, but using PeriodStart as the anchor makes the logic correct if Fortnox updates PeriodEnd independently.

#### 2. "Enrich & Format Order" (Code node, ID: `0b958555`)

Current code references PeriodEnd in three places:

| Line | Current | Change To |
|------|---------|-----------|
| `deliveryDate` | `contract.PeriodEnd` | `nextPeriodStart` (calculated from PeriodStart + Interval) |
| `YourOrderNumber` | `C${DocNum}-${PeriodEnd}` | `C${DocNum}-${nextPeriodStart}` |
| `periodStartStr` | `PeriodStart + Interval` | Keep as-is (already correct) |

#### 3. "Filter Active & Ending in X Days" (IF node)

If this node has a condition referencing PeriodEnd, it also needs updating.
