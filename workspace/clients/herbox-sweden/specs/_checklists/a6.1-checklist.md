## Notes

**Special considerations for A6.1:**

1. **Queue Management:** This automation respects a 4-concurrent-scraper limit. To test queue behavior:
   - Either have 4 scrapers running (hard to coordinate)
   - Or temporarily modify `MAX_CONCURRENT_SCRAPERS` to a lower number for testing

2. **LinkedIn Cookies:** These are stored in Airtable, not environment variables. This allows:
   - Easy rotation without redeployment
   - Multiple backup accounts
   - Non-technical users can update cookies

3. **Dry Run Mode:** The automation has smart dry-run handling:
   - Skips fetching real LinkedIn cookies (uses mock)
   - Doesn't actually start the Apify actor
   - Shows what config would be used

4. **Webhook vs Direct Trigger:**
   - **Webhook (`/webhook/apify-scraper-starter`)**: For production use by A6 orchestrator
   - **Direct execution**: For testing with `--dry-run` flag

5. **Background Processing:** The webhook returns immediately. Actual processing happens in background. Check Railway logs for details.
