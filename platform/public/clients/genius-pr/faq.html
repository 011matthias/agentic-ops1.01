Pricing

Why $1,500 when the budget is $500? +

Scope reality. Three workflows, 11 integrations, AI classification with confidence gating, contact deduplication, error handling with Slack alerts, and 5 real leads tested end-to-end.

At $500 that is roughly $45 per integration to set up, test, handle edge cases, and document. That budget buys happy-path connections with no error handling. The first time an API changes its payload format or Claude returns an unexpected response, the system breaks silently. You do not find out until a hot lead falls through and no one notices for a week.

We build production systems, not happy-path demos. The gap between the two is mostly invisible until the demo goes to production and breaks.

Can you do the work at $500 with reduced scope? +

The minimum viable version at $500 would be Workflow 1 only (AI Reply Classifier), with happy-path connections and no error handling or confidence gating. That is 4–5 integrations instead of 11, one workflow instead of three.

That is a different product. You would get the classification logic and basic routing, but without the safety net that makes auto-response viable. We would rather be direct about this than build something that fails in production and reflects poorly on both parties.

If budget is genuinely fixed at $500, we can discuss a phased approach: Workflow 1 with confidence gating for $500, then Workflows 2 and 3 in a second engagement.

How is payment structured? +

Via Upwork milestones. 50% ($750) to start when we agree the contract. 50% ($750) on delivery when all three workflows are live and tested. Standard Upwork escrow protects both parties.

No payment until we start. No final payment until you have working workflows in your hands.

Delivery

Can you deliver in 7 days? +

Yes, if API access and credentials are ready on Day 1. The timeline is tight but realistic because we have built similar systems before. We are not figuring out the Instantly API or HubSpot Private Apps for the first time on your project.

Credential delays are the single biggest risk to the timeline. If HubSpot access takes 2 days to provision, that pushes everything. The onboarding checklist shows exactly what needs to be ready before we start. If you can have all credentials ready before Day 1, the 7-day timeline holds.

What happens if something breaks after delivery? +

The maintenance guide covers the most common failure scenarios: HubSpot API changes, n8n credential expiry, rate limit errors. Most issues are fixable by a non-technical user following the guide.

For anything the guide does not cover, post-delivery support can be arranged separately. We are not going to vanish after handoff. If an API changes its format and breaks the workflow, we will tell you what changed and how to fix it.

The n8n workflows are also exported as JSON files. Any n8n developer can pick them up and make modifications without needing us.

What if we are not happy with the result? +

The final milestone is not released until you confirm the workflows are working as specified. We test 5 real leads with you before calling it done. If classification is wrong, if a Slack alert is missing, if a HubSpot record is not created correctly, we fix it before requesting the final payment.

The scope is defined in this proposal. If the delivered system matches the scope and you are still unsatisfied, Upwork's dispute resolution process applies. We have a 100% job success score on Upwork because we do not ship things that do not work.

Technical

Why Claude API instead of GPT? +

We use Claude daily for classification and structured output tasks. Claude consistently follows structured JSON output instructions precisely, which matters for reliable routing. When we ask Claude to return a specific JSON schema with a classification field and a confidence field, it does that. Every time.

GPT-4 also works well for this. The system can be adapted to use GPT if you have a strong preference or an existing OpenAI credit balance. The prompt engineering approach is the same. We default to Claude because it is what we know produces reliable results for this use case.

What happens when the AI gets it wrong? +

Confidence threshold gate. If Claude returns a confidence score below 80%, the reply routes to a manual review Slack channel instead of auto-responding. No auto-reply is sent. A human reviews and responds.

This means the only leads that get auto-responses are the ones Claude is highly confident about. In practice, genuinely ambiguous messages (the ones most likely to be misclassified) route to human review. You get the speed benefit for clear-cut HOT leads while maintaining human oversight for anything uncertain.

The 80% threshold is configurable. We tune it during the testing phase based on how Claude performs on your actual lead messages.

What if Dripify webhooks are not available? +

Dripify has no public API. Webhook support requires their Pro plan at $59/month. If you are on a Basic plan, native Dripify integration is not possible.

In this case, we handle LinkedIn via HeyReach as the primary channel. For Dripify specifically, two alternatives work: manual CSV export on a schedule (you export, we import), or a Zapier bridge if you have a Zapier account (Zapier has a Dripify integration that can trigger our n8n webhook). We agree the approach before Day 1 so it does not block the timeline.

Do we need to set up Railway ourselves? +

No. We set up the Railway n8n instance together on Day 1. Railway is straightforward to provision, and we have done it multiple times. You create the Railway account and we handle the n8n deployment and configuration.

Railway hosting for n8n typically runs $10–20 per month depending on usage. That is billed directly to your Railway account, not included in the project price.

Risk and Security

Do you handle ongoing maintenance? +

The deliverable is a working system with documentation. The maintenance guide covers the most common scenarios. Post-delivery maintenance can be arranged separately if needed.

The system is designed to run without intervention. n8n handles the orchestration, Railway keeps it running, and the error handling alerts you via Slack if anything breaks. Most issues surface as a Slack alert with enough detail to diagnose and fix without us.

What about data security? +

All API keys are stored in n8n's encrypted credentials vault, never hardcoded in workflow nodes. HubSpot integration uses Private App API tokens with scoped permissions (contacts, deals, timeline, tasks only). No broad API keys.

All data flows through your own Railway-hosted n8n instance. Replies and contact data do not pass through our infrastructure. The only external service handling your data is Claude API (Anthropic), which processes the message text for classification. Anthropic's API does not train on API usage by default.

We do not retain access to your Railway instance or n8n after delivery. Credentials are stored in your vault, not ours.

What is the risk if we proceed? +

The main risks are timeline slippage due to credential delays (mitigated by the onboarding checklist) and AI misclassification on edge-case messages (mitigated by the confidence threshold gate and real-lead testing).

The financial risk is structured via Upwork milestones. You do not release the final 50% until the system is working. If we fail to deliver, you keep the milestone funds via Upwork's dispute process.

The risk of doing nothing is continuing to manually triage every reply and losing HOT leads to slow response times. Response time is the most measurable variable in lead conversion. This system responds in seconds.
