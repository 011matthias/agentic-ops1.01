Architecture Overview

The platform has four layers: channel ingest (leads from SAP, website, LinkedIn), the core processing pipeline (classify, score, draft, route), email sending via SMTP, and a unified dashboard for approvals and conversation management. The CRM layer is abstracted: Zoho CRM is the first connector, but the system defines a standard set of events (Create Lead, Add Comment, Update Status, Attach Email) so swapping CRM later means writing a new connector, not reworking the logic.

Lead nurturing is the first use case. The architecture is designed so the same layers handle future use cases (invoice routing, compliance emails) by adding new ingest channels and processing rules without rebuilding the core.

The design principle is separation of concerns: the ingest layer handles the messiness of each source channel (different email formats, different webhook payloads) so that A3 always works with clean, consistent data. Adding a new channel or use case means adding a new ingest workflow, not changing the pipeline.

Three workflows handle lead capture from the active source channels. Each channel arrives via a different method and carries different context. The ingest layer extracts that context and normalizes it into a standard lead record for the pipeline.

Follow-Up Pipeline (A3)

A3 is the core of the system. It receives normalized lead records and takes them from raw input to a sent (or queued-for-review) first response. Five stages run in sequence.

Stage 1 - Validation and Deduplication

Before any processing, A3 checks that the lead has a valid email address and that the same contact has not already been processed recently. Duplicates are logged and dropped. Invalid records (missing email, clearly spam) are flagged and skipped.

Stage 2 - Classification and Scoring

Each lead is classified into one of four tiers: SPAM, Low, Medium, or High. Classification and spam detection happen in a single step. Each signal carries a numeric weight; the total determines the tier. The weight table is configurable, not hardcoded, so thresholds and signal importance can be adjusted over time without code changes.

SignalWeightRationale
SAP Store source+5Strongest intent signal: active product inquiry with product context
Company email domain (non-Gmail)+3Business contact, not personal
Company name provided+2More detail = more serious inquiry
Message length and specificity+2Specific question signals genuine interest
Channel context present (product, UC, campaign)+2Richer context = better response possible
SAP Discovery Center source+1Higher volume, mixed quality
Gmail or generic email only-2Lower confidence without company context
Spam indicators (gibberish, known patterns, no real content)-10Drops lead below spam threshold
Configurable weight table

Weights and tier thresholds are stored in the system configuration, not in code. Adjustments are made by editing the config table directly. Fine-tuning works by reviewing misclassified leads and adjusting weights. Automated tuning (system suggests weight changes based on outcomes) is a later-phase feature once enough lead history exists.

Tier thresholds (example ranges, configurable):

SPAM: below 0 Low: 0 to 4 Medium: 5 to 9 High: 10+
Spam
Dropped. No response, no CRM entry, no AI spend. Logged for audit.
Low
Response sent automatically. Shorter, template-based. Logged to CRM. Less AI context loaded.
Medium
Response sent automatically with richer context. Reviewer notified. Can follow up if needed.
High
Held for human review before sending. Full context package: lead record, enrichment, AI draft, channel context.
All non-spam leads get a response

The system does not filter out low-ranked leads. Every lead that is not spam receives a response. The difference is effort: higher-ranked leads get more context loaded into the AI draft, richer personalization, and human review before sending. Lower-ranked leads get a simpler but still relevant response sent automatically.

Stage 3 - Contact Enrichment (optional)

For High and Medium leads, A3 can attempt a basic company lookup using the email domain or company name field. This gives the AI more context for drafting a relevant response. This step is optional and can be toggled per tier if the cost or latency is not acceptable.

Stage 4 - AI Response Drafting

AI drafts a first response using a structured prompt. The prompt constrains the output to: acknowledge the specific inquiry, reference the lead's stated interest, provide relevant context about Brisken's offering, ask one qualifying question, and indicate that a follow-up will come. Docs or links can be attached based on the source channel. All responses are sent via SMTP from Dirk's personal corporate email, not from a generic address.

AI constraints

The model is given a strict template and is not free-form. Responses are reviewed before sending for High-tier leads. Tone, length, and structure are all controlled in the prompt. This is not ChatGPT replying however it likes.

Stage 5 - HITL Routing and Send

Based on the tier from Stage 2, the draft is either sent directly or routed to a review queue via the unified dashboard. Dirk sees the full lead context, the AI draft, and approve / edit / reject options. Approved responses are sent via SMTP from Dirk's email, preserving the email thread. Follow-ups for unresponsive leads are always replies to the existing thread (never a new email), so the full conversation history stays intact. Each event (sent, approved, rejected) is pushed to the CRM via the abstraction layer (Create Lead, Add Comment, Update Status). Currently wired to Zoho; swapping CRM later means writing a new connector, not changing this pipeline.

Reply Monitoring (A4)

Since the automation sends via SMTP but does not have access to Dirk's inbox, replies are captured via an Outlook auto-forward rule. Replies land in a dedicated monitored mailbox. A4 polls this mailbox at a configurable interval and matches incoming emails to outbound leads using thread ID and sender. When a reply is detected, two things happen immediately: any pending follow-up sequence for that lead is cancelled, and the reply is escalated to human review via the dashboard.

Dirk's requirement - all second responses are human

There is no automated second response under any circumstances. When a lead replies, the conversation moves to human hands. A4 surfaces the full context - original lead record, first response sent, reply received - so the reviewer has everything needed to continue the conversation.

The escalation notification includes: the lead's original record, the first response that was sent, the reply text, and the recommended next action. The reviewer does not need to search for context.

Data Flow

End-to-end, a lead moves through the system as follows:

StepWorkflowWhat happens
1. ArriveA0 / A1 / A2Lead arrives via email, webhook, or API. Raw payload is captured.
2. NormalizeA0 / A1 / A2Source-specific parsing extracts fields. Standard lead record is created with a UUID.
3. ValidateA3Email validity and deduplication check. Duplicates and invalids are dropped with a log entry.
4. ClassifyA3Spam filter + scoring in one step. Numeric weights summed, mapped to tier (SPAM/Low/Medium/High). Spam leads dropped here.
5. EnrichA3Optional company lookup for High/Medium leads. Appended to lead record.
6. DraftA3AI drafts a first response using lead context and channel-specific templates.
7. RouteA3High: held for review. Medium/Low: sent automatically with optional notification. All non-spam leads get a response.
8. LogA3Events pushed via CRM abstraction layer: Create Lead, Add Comment, Update Status. Zoho is the first connector.
9. MonitorA4Inbox polled for replies. Match found = cancel follow-up sequence.
10. EscalateA4Reply escalated to human reviewer with full context package. No auto-response.
