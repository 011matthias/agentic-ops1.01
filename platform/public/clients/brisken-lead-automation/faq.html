Technical

What platform will this run on?

The platform choice is currently being evaluated. Three options are on the table: n8n (workflow automation tool with visual interface), Firebase/Cloud Firestore (Google's all-in-one platform with database, auth, hosting, and functions), or a custom-coded solution (e.g., Next.js + database).

Each has different trade-offs around development speed, dashboard capabilities, multi-tenant readiness, and ongoing cost. A recommendation will be provided before the build starts. The choice does not affect what the platform does, only how it is built and hosted.

How does the email sending work?

All outbound emails are sent via SMTP using Dirk's personal corporate email credentials. The automation does not have access to Dirk's inbox. Replies are captured via an Outlook auto-forward rule that routes them to a dedicated monitored mailbox. This means the automation can send as Dirk and detect replies without needing inbox access.

Follow-ups always reply to the existing email thread so the full conversation history is preserved. The lead never receives a disconnected email.

What AI model is used for response drafting?

The specific model will depend on the platform choice, but the approach is the same: AI operates within strict templates and constraints, not free-form generation. Every draft follows the structure defined in advance: acknowledge the inquiry, reference the specific product interest, provide relevant information, and ask a follow-up question.

Multiple AI providers can be used (OpenAI, Anthropic, Azure OpenAI, Google). The system is provider-agnostic.

How does the SAP email parsing work?

SAP Discovery Center and SAP Store send email notifications when someone expresses interest. The system polls the designated inbox on a schedule (every 10 minutes by default), identifies SAP notification emails by sender and subject pattern, and extracts the lead fields (name, email, company, product interest) from the email body using pattern matching.

We need sample notification emails from both channels to build the parsing templates. SAP notification formats are consistent, so once the template is built it handles all future emails from that channel reliably.

What about LinkedIn API restrictions?

This is an active investigation item. LinkedIn has bot detection that can flag or temporarily suspend accounts that use API messaging heavily. We are evaluating whether outbound messaging via API is viable at Brisken's volume.

If API sending is restricted, the fallback is a manual-send workflow: the system drafts the response and presents it in the dashboard, and Dirk copies it into the LinkedIn chat. At 10 leads per week, this takes about 30 seconds per lead and avoids any API risk.

Process

How does the human review work?

First response routing by tier:

  • High: AI draft is held for human review before sending. Reviewer sees full context package (lead record, channel context, enrichment data, draft).
  • Medium: Response auto-sent. Reviewer notified with full context. Can follow up if needed.
  • Low: Response auto-sent. Logged to CRM. Simpler response with less AI context loaded.
  • Spam: Dropped entirely. No response, no CRM entry.

All replies (every tier): When any lead responds to a first message, the reply goes to mandatory human review. No automated second response under any circumstances, regardless of lead tier. The tool accompanies the entire conversation lifecycle, but second responses always go through a human.

Can I adjust the lead scoring criteria?

Yes. The scoring weights and tier thresholds live in a configurable table, not in code. You can add or remove scoring signals, change the numeric weight of each signal, and adjust the score ranges that map to SPAM / Low / Medium / High. For example, you could increase the SAP Store weight from +5 to +7, or lower the High threshold from 10 to 8.

Fine-tuning works by reviewing leads that were classified incorrectly and adjusting the weights accordingly. Automated tuning (system suggests changes based on outcomes like reply rates and conversions) is planned for a later phase once enough lead history exists.

What happens when a lead comes from a new channel?

We add a new ingest workflow that follows the same pattern as the existing ones (A0, A1, A2). It normalizes the new channel's data into the standard lead schema and feeds it into the existing pipeline (A3). The pipeline itself does not need to change because it works with normalized data, not raw channel formats. Adding a new channel is an isolated addition, not a system modification.

What does the first response look like?

The AI drafts a personalized email that follows a consistent structure: (1) acknowledge the inquiry and thank them for their interest, (2) reference the specific product or use case they asked about, (3) provide relevant additional information or documentation, (4) ask a clarifying question to move the conversation forward. The tone, style, and content guidelines are configured based on your preferences. You review and approve the templates and guidelines before the system goes live.

Scope

Can we start with just lead nurturing?

Yes. Lead nurturing is Phase 1-3 and is independently valuable. Phase 1 gives you automated lead capture from SAP and website channels. Phase 2 adds scoring, AI drafting, and human review gates. Phase 3 adds reply monitoring. The platform extensions (invoice routing, compliance, LinkedIn management) build on the same infrastructure once the lead pipeline is stable.

How does invoice/AP routing work?

Same architecture as lead nurturing, different use case. Invoices arrive via email, the system auto-forwards them to the relevant expense owner for approval (e.g., Giuliano), tracks the approval status, and notifies Chris for payment. Events are logged to Zoho CRM. This replaces the current manual email forwarding workflow that takes 15 minutes per day.

An alternative path is to skip email entirely and create accounts payable entries directly in Zoho, with approval routing built in. Both options will be evaluated.

What does "multi-tenant" mean here?

The platform is designed so that multiple organizations can use the same system with isolated data. For example, Brisken and another Dirk entity could each have their own dashboard, their own leads, their own email settings, but run on the same platform. This does not add significant complexity if built in from the start. Initially, only Brisken will be active.

Is LinkedIn confirmed as a channel?

Not yet confirmed for lead ingest, but the scope has expanded: Dirk wants all LinkedIn messages visible in the dashboard, not just lead gen form submissions. The system would assist with response drafting and conversation tracking across LinkedIn. API restrictions for outbound messaging are being investigated.

What if we want to switch away from Zoho CRM?

The system communicates with the CRM through an abstraction layer that defines standard events: Create Lead, Add Comment, Update Lead Status, Attach Email. Zoho is the first connector built for this layer. Switching to a different CRM (HubSpot, Salesforce, Pipedrive, or anything with an API) means writing a new connector that maps these same events to the new CRM's API. The pipeline logic, scoring, AI drafting, and review workflows stay untouched.

Data and Privacy Updated 2026-04-16

Where is lead data stored?

Lead data lives in the platform's database. The specific store depends on the platform decision still open on the Overview page: a custom multi-tenant SaaS backend with its own database, or Firebase / Firestore. Zoho CRM receives event updates as an async activity log. The only external call with lead content is to the AI provider for response drafting, where the minimum necessary context (name, company, inquiry) is sent to generate the draft.

Does the automation have access to my inbox?

No. The automation sends via SMTP (outbound only) and does not read Dirk's inbox. Replies are captured via an Outlook auto-forward rule to a separate monitored mailbox. This is a deliberate architectural choice: the automation can send as Dirk and detect replies without needing corporate email access. Your 2026-04-13 comment floated a unified SMTP-based mail capture as an alternative; that is being evaluated for phase 2.

Is this GDPR compliant?

GDPR compliance is a hard requirement per your 2026-04-13 note, not a nice-to-have. The scope covers:

  • Retention. Default retention windows per data class (lead records, email threads, AI drafts, activity log). Configurable per tenant.
  • Right to delete. A documented flow for erasing a contact's data from the system on request, including downstream references in the CRM event log.
  • Residency. EU-region hosting + storage; region choice slots into the platform decision.
  • Subprocessors. A short list (AI provider, CRM, hosting); DPAs reviewed and linked in the tenant admin settings.
  • Processing basis. B2B contact data for responding to inbound inquiries (legitimate interest). No behavioural profiling, no third-party ad tech.

Implementation specifics land once the platform decision is made. We will circulate a short GDPR checklist for your legal review before phase 1 ships.

What gets logged for auditing?

Every event on a lead is captured: receipt timestamp, classification result, enrichment calls, AI draft generation, HITL decision (approve / edit / reject), send timestamp, replies, follow-ups. The activity log serves two purposes: a GDPR-grade audit trail if you ever need to show what the system did with a contact's data, and a training signal for the learning classifier so that your review decisions improve the scorer over time. Added as a first-class requirement per your 2026-04-13 note.

Can the AI be turned off?

Yes. The AI response drafting step is a configurable part of the pipeline, not a hard dependency. If you prefer to use static email templates instead of AI-generated drafts, the system routes leads through the same scoring and review process but sends a template-based response instead. You can also run in "draft only" mode where the AI generates drafts but every response goes through human review before sending.
