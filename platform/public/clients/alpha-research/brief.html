Project Brief

Your Requirements, Mapped

We read both job postings carefully. Here is what you asked for, organized by scope, with links to where each requirement is addressed in this proposal.

Job 1: Dynamic Web Scraping Pipeline

Build a dynamic web scraping pipeline using n8n for investment research across 300+ companies. The system must handle diverse website structures, extract financial documents, and deliver structured data.

Core Requirements

  • Scrape investor relations pages for 300+ companies
  • Handle diverse website structures (static HTML, JavaScript-rendered, PDF-heavy)
  • Extract and classify financial documents (annual reports, quarterly filings, presentations)
  • Deliver structured JSON output per company

Technical Requirements

  • Built entirely in n8n
  • Batch processing with rate limiting
  • Error handling and retry logic
  • Deduplication across scraping runs
  • Cloud storage integration

"To Apply" Questions (Job 1)

  1. Technical approach for handling diverse website structures?
  2. How will you handle edge cases (Cloudflare protection, dynamically loaded content, rate limiting)?
  3. Experience with AI-assisted parsing for financial document extraction?
  4. Time estimate for building the initial scraping pipeline for 5-10 site types?
  5. Cost estimate for the project?

Job 2: AI Document Processing + News + HITL

Build an AI-powered document processing, news filtering, and human-in-the-loop pipeline. The system synthesizes investment thesis files, monitors relevant news, and routes updates through email-based approval before modifying core research documents.

Core Requirements

  • Monitor for new analysis files in cloud storage
  • Synthesize findings against existing thesis documents
  • Filter news from multiple sources (APIs, RSS) by relevance
  • Human-in-the-loop email approval before any file modification

Technical Requirements

  • Built in n8n with AI/LLM nodes
  • Tavily web search integration
  • AlphaVantage + SerpAPI + RSS news sources
  • Wait node + Webhook for HITL approval
  • Markdown file append (section-targeted)

"To Apply" Questions (Job 2)

  1. HITL architecture: How will you implement email-based approve/reject with file modification?
  2. File management: How will thesis files be updated without losing existing content?
  3. Time estimate for the complete pipeline?
  4. Cost estimate for the project?

Why One System

These two jobs share one hard problem: getting structured data out of unstructured sources. The web scraper extracts document links from messy HTML. The thesis synthesizer extracts insights from messy markdown. The news filter extracts relevance from messy articles. Same pattern, same infrastructure.

Job 1: Web Scraping
  • HTTP + browser scraping
  • HTML parsing
  • Document download
  • Batch processing
Shared Infrastructure
  • Company registry
  • Cloud storage
  • LLM extraction
  • Error handling
  • n8n orchestration
Job 2: AI Processing
  • Thesis synthesis
  • News filtering
  • HITL approval
  • File management
One build, two deliverables

Building these as one system means: one Google Sheets company registry (not two), one cloud storage layer (not two), one error handling pattern (not two), and one place to debug when something breaks. You get two exportable n8n workflow templates that share infrastructure.
