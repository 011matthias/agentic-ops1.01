Why 3 weeks

The estimate accounts for pipeline complexity: 5 interconnected workflows, 4 external API integrations, AI-powered extraction with prompt tuning, and a HITL approval flow that requires email + webhook coordination. Each phase builds on the previous one and includes testing plus buffer for API integration issues and edge cases in 300+ website structures. Typical agency timelines for comparable AI automation projects are 4–8 weeks. The shorter timeline is possible because we use proven n8n pipeline patterns and pre-built Claude AI integration templates.

Phase 1: Foundation (Days 1-6)

Data ingestion pipelines. This phase builds the core scraping infrastructure: how companies get queued, how pages get fetched, how documents get extracted and stored.

Days 1-2: Registry + Dispatcher Skeleton

  • Google Sheets company registry setup — columns for ticker, company name, IR page URL, scrape status, last run timestamp
  • Dispatcher workflow skeleton — Schedule Trigger reads the registry, splits into controlled batches, passes each company to the scraper sub-workflow
  • Schedule Trigger configuration — configurable frequency (daily/weekly), batch size limits to avoid rate limiting

Days 3-4: Scraper Sub-Workflow

  • HTTP scraper sub-workflow — receives company data from dispatcher, fetches the investor relations page via HTTP Request node
  • Code node HTML parsing — extracts all links from the page, normalizes relative URLs, filters by file extension and path patterns
  • AI link extraction with Claude — LLM classifies each link (annual report, quarterly filing, presentation, other), assigns confidence score, handles ambiguous naming

Days 5-6: Browser API + Storage + Integration Testing

  • Browser API integration (ScrapingBee/Bright Data) — fallback for JavaScript-rendered investor relations pages that HTTP Request cannot handle
  • Deduplication logic — hash-based dedup to avoid re-downloading documents already in storage, comparison against previous scrape results
  • Cloud storage integration — organized folder structure by ticker symbol, automatic file naming conventions, metadata tagging
Phase 1 Deliverable: Working dispatcher that scrapes 5-10 test companies end-to-end. Registry reads, pages fetch, links extract, documents download to cloud storage.

Phase 2: Intelligence (Days 7-11)

Processing pipelines. This phase builds the analytical layer: thesis synthesis, news filtering, and the human-in-the-loop approval flow that prevents any automated overwrites.

Days 7-8: Thesis Synthesis Pipeline

  • File watcher trigger — monitors cloud storage for new analysis files uploaded by the research team
  • Multi-document fetch — retrieves the four core thesis documents (Core Thesis, Supporting Evidence, Risk Factors, Valuation Notes) for the affected company
  • Claude synthesis prompt — LLM reads new analysis against existing thesis, identifies what needs updating, what contradicts, what reinforces
  • Section-targeted markdown append — proposed changes written as structured markdown diffs, ready for human review before merging into thesis files

Day 9: News Intelligence Filter

  • Multi-source news aggregation — Tavily + AlphaVantage + SerpAPI + RSS feeds, each queried per company in the registry
  • Merge + deduplication — combines results from all sources, removes duplicates by URL and headline similarity
  • Claude relevance scoring — LLM scores each article against the company's Core Thesis, flags material deviations, filters noise below configurable threshold

Days 10-11: HITL Email Approval Flow

  • HTML email generation — formatted email showing proposed changes with full context (source documents, confidence scores, diff preview)
  • Signed webhook URLs — unique Approve/Reject links embedded in the email, cryptographically signed to prevent tampering
  • Wait node integration — n8n Wait node pauses execution until the analyst clicks Approve or Reject in the email
  • Approve/reject handling — Approve merges changes into thesis files, Reject logs the decision with optional analyst notes for future reference
Phase 2 Deliverable: All 5 pipelines functional in sandbox with test data. Thesis synthesis triggers on file upload, news filter scores articles against thesis, HITL emails send and process responses.

Phase 3: Test + Deliver (Days 12-15)

Production readiness. This phase hardens everything: real data, edge cases, prompt quality, error handling, and documentation for handoff.

Days 12-13: End-to-End Testing

  • Full pipeline test with 5-10 real companies — dispatcher through to cloud storage, thesis synthesis through to email approval
  • Edge case handling — broken investor relations pages, HTTP timeouts, missing documents, malformed HTML, empty search results
  • Error recovery — failed companies retry on next run, partial failures do not block the batch, error states logged to the registry

Day 14: LLM Prompt Tuning

  • Extraction accuracy — review AI link classification results across all test companies, adjust prompts for edge cases (sites with unusual naming, multi-language pages)
  • Relevance scoring thresholds — calibrate the news filter cutoff so material news passes through while routine press releases get filtered
  • Synthesis quality — review thesis update proposals for accuracy, specificity, and actionability against analyst expectations

Day 15: Handoff

  • Error handling audit — every failure path has a handler, every timeout has a fallback, every error logs context for debugging
  • Execution logging — run history with per-company success/failure, timing data, API call counts for cost tracking
  • Documentation — operations guide covering configuration, troubleshooting, adding new companies, adjusting thresholds
  • JSON export of both workflows — two complete n8n workflow files ready to import into any n8n instance
Phase 3 Deliverable: Two tested n8n workflow JSON exports, operations documentation, and handoff. Production-ready system processing real companies with tuned prompts and full error handling.
