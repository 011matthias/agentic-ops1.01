UK Events Company: Make.com Pipeline

A wedding and events venue company in the UK. They needed a full automation backbone to handle enquiry intake, qualification, personalized follow-up, and team routing. Before my work, their process was manual email triage with responses that took hours or days.

What I Built

15 production Make.com scenarios that form a connected pipeline:

  • Enquiry intake: Website form submissions captured via webhook, parsed, and stored in a MySQL database with full field validation
  • AI-powered classification: Each enquiry is scored by intent and urgency using AI APIs. Confidence thresholds determine whether it routes automatically or flags for human review
  • Personalized email sequences: Based on classification results, the system triggers the right email template via Mailgun with dynamic merge fields pulled from the database record
  • Team routing: High-value enquiries route to specific team members based on venue type and availability. Lower-priority items enter a nurture sequence
  • Structured logging: Every scenario writes to a centralized error log. Failed operations include the specific module, input data, and error message for fast debugging

Systems Used

Make.com (15 scenarios), MySQL, Google Sheets, Mailgun, AI APIs (classification and generation).

Why this matters for your agency

This is the kind of multi-scenario Make.com architecture your clients might need. I've built it, maintained it, and iterated on it in production over multiple months. Error handling and monitoring aren't theoretical for me. They're things I debug at 8am when a scenario fails overnight.

EU Healthcare Startup: n8n Deployment

A healthcare startup building patient journey automation. Different industry, different compliance requirements, different orchestrator. The methodology stays the same.

What I Built

  • Webhook-based intake: Patient form submissions trigger workflows that validate, transform, and route data through the pipeline

AI-Powered Classification Pipeline

A project where the core challenge was routing incoming messages to the right team without human triage. The client received hundreds of inbound messages daily across email, forms, and chat. Each one needed to go to sales, support, or billing based on content, not keywords.

What I Built

  • Confidence-threshold routing: Each message gets classified by AI with a confidence score. High-confidence messages route automatically. Low-confidence ones get flagged for human review. This means the system handles the easy 80% without intervention and only escalates the ambiguous 20%.
  • Multi-channel intake: Webhooks capture messages from three sources into a unified format before classification. The AI doesn't care where the message came from.
  • Feedback loop: When a human overrides a classification, that correction feeds back into prompt refinement. The system gets more accurate over time without retraining a model.
  • Audit trail: Every classification decision is logged with the input, output, confidence score, and routing action. Useful for debugging and for demonstrating accuracy to stakeholders.

Systems Used

Make.com (orchestration), OpenAI API (classification), Google Sheets (audit log), webhooks (multi-channel intake).

The pattern behind this

AI classification + confidence routing is one of the most common patterns I build. It applies to support tickets, lead qualification, content moderation, document routing. The structure is the same, the prompts change. If your clients have any "sort this pile of incoming stuff" problem, this is the solution.
