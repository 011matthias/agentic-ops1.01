Frequently Asked Questions

Common questions about the project, the technology, and how we work together.

What if our support tools don't have APIs?

Most modern ticketing systems (Zendesk, Freshdesk, Intercom, HubSpot Service Hub) have REST APIs and webhook support. For tools without native APIs, we can use email parsing as a fallback trigger, or bridge through Zapier/Make.com for the initial integration.

During discovery week, we'll audit every tool in your stack and flag any that need a workaround.

How accurate is the AI classification?

Classification accuracy depends on the quality of the training examples and the specificity of the categories. In our experience, Claude API hits 85-90% accuracy on well-defined categories after initial tuning.

The confidence threshold gate means low-confidence classifications always go to a human. We track accuracy weekly and adjust prompts and thresholds based on real results.

What happens when the AI gets it wrong?

Every classification below the confidence threshold routes to a human reviewer (Tier 1). For auto-resolved tickets (Tier 0), we include a "Was this helpful?" feedback mechanism. If a customer says no, the ticket reopens and escalates to Tier 1 with full context.

Wrong classifications are logged and used to improve the prompt.

Can this work with our existing n8n instance?

Yes. The workflows are exported as standard n8n JSON files. Import them into your instance, configure the API credentials, and they run.

If you don't have n8n yet, we'll set it up during Week 1 (self-hosted or cloud, your choice).

What happens when something breaks at 3am?

Every workflow has built-in retry logic with exponential backoff. If retries fail, the ticket goes to a dead letter queue and a monitoring alert fires to Slack. Nothing gets lost silently.

The retainer includes monitoring response during business hours. For critical P1 issues, we can set up PagerDuty integration.

How do you handle GDPR with AI processing?

I'm based in Germany, so GDPR is native to how I work. Customer data stays in your infrastructure (your n8n instance, your CRM, your Slack). The Claude API call sends only the ticket text for classification, not customer PII.

We can add a PII scrubbing step before the API call if needed. No data leaves the EU unless your tools are US-hosted.

Why not just use ChatGPT with Zapier?

You can, for simple use cases. The difference is in the decision-making layer. A Zapier + ChatGPT setup gives you text generation. What you need is structured classification with confidence scoring, threshold-based routing, and escalation logic.

That requires a proper orchestrator (n8n) and structured API output (Claude with JSON schemas), not a chat completion endpoint.

What's MCP and why does it matter?

MCP (Model Context Protocol) is a standard for connecting AI models to external tools in real time. Instead of the AI just generating text, MCP lets it query your CRM, check your knowledge base, or trigger actions directly.

It's listed as a "nice-to-have" in the job posting, but it's core to how I build systems. The proposal pipeline that generated this site uses MCP connections to Make.com and n8n servers daily.
