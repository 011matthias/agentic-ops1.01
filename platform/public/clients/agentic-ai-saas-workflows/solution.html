Three-Tier AI Support Architecture

Every ticket enters through the same webhook endpoint. The Claude API reads the ticket content and returns a structured JSON classification with five fields: category, priority, confidence, suggested_action, and escalation_tier. That classification determines what happens next.

The confidence score is the routing key. It controls which tier handles the ticket.

Decision Tree

Condition Result Action
Confidence > 0.85 + known issue pattern Tier 0 Auto-resolve. Generated response sent to customer, ticket closed.
Confidence 0.5 to 0.85, or unknown pattern Tier 1 Agent-assisted. Context enrichment + Slack summary for support team.
Bug/infrastructure flag, or P1 severity Tier 2 Engineering escalation. Structured bug report generated automatically.

Structured JSON output

The Claude API call uses a strict JSON schema. Every classification returns the same five fields, so downstream routing never breaks on unexpected formats. The schema is versioned, and any changes go through the confidence calibration review process.

Agent 1: Auto-Resolver

The auto-resolver handles tickets where the system is confident it knows the answer. These are known issues with documented solutions: password resets, billing FAQ, status page questions, configuration how-tos. The goal is sub-30-second resolution with zero human involvement.

How it works

  1. Webhook trigger receives the incoming ticket payload (subject, body, customer ID, metadata)
  2. Claude API classifies the ticket with structured JSON output (category, priority, confidence, suggested_action, escalation_tier)
  3. Confidence gate checks the score. Only tickets above 0.85 with a known issue pattern match proceed here.
  4. Response generator creates a customer-facing reply using the knowledge base article that matched. The tone matches your brand voice.
  5. The generated response is sent to the customer through your existing email or ticket system.
  6. Ticket gets tagged with the classification category, logged with the full decision trace, and closed in your CRM.
Target: resolution time < 30 seconds
Safety net

If the customer replies to an auto-resolved ticket, it automatically re-opens and escalates to Tier 1. The auto-resolver doesn't argue with customers.

Agent 2: Agent-Assisted Support

Medium-confidence tickets need human judgment, but they don't need human research. This agent does the context-gathering work so your support team can focus on the decision.

How it works

  1. Ticket arrives with a confidence score between 0.5 and 0.85, or it matches an unknown pattern the system hasn't seen before.
  2. Context enrichment pulls three data sources: CRM history for this customer, knowledge base articles matching the ticket content, and previous tickets from the same customer.
  3. The system builds a structured summary: ticket content, classification result, suggested response draft, and links to relevant documentation.
  4. That summary gets pushed to a dedicated Slack channel. Your support team sees everything they need in one message.
  5. The support agent reviews the suggested response, edits it if needed, and approves it.
  6. One-click send from Slack delivers the approved response to the customer. The ticket updates in your CRM automatically.
Why this matters

Your team doesn't waste time searching CRM records or digging through documentation. They walk into every ticket with full context already assembled. The suggested response gives them a starting point, not a final answer.

Agent 3: Engineering Escalation

When the classification detects a bug report or an infrastructure issue, the ticket needs to reach engineering with enough context to act on it. This agent generates structured bug reports that engineers can triage without asking follow-up questions.

How it works

  1. The classification flags the ticket as a bug or infrastructure issue based on content analysis. P1 severity tickets also route here regardless of category.
  2. The system generates a structured bug report: title, reproduction steps extracted from the ticket, affected systems, severity assessment, and customer impact summary.
  3. That bug report gets routed to your engineering project management tool (Linear, Jira, GitHub Issues, or similar).
  4. The customer receives an acknowledgment message with an expected response time based on the severity level.
  5. The original support ticket links back to the engineering issue for status tracking. When engineering updates the issue, the customer can be notified.
Structured output

Engineers don't need to read raw customer emails. The bug report is already formatted with reproduction steps, severity, and affected systems. This saves one round-trip of "can you provide more details?" on most escalations.

Shared Infrastructure

All three agents run on the same foundation. This isn't three separate systems bolted together. It's one system with three output paths.

Error Handling
Resilience built into every step
  • Retry logic with exponential backoff on API calls
  • Dead letter queue for tickets that fail classification
  • Graceful degradation: if Claude API is down, tickets queue for manual triage
  • Per-step error logging with full request/response capture
Monitoring
Visibility into every classification decision
  • Execution logs for every ticket processed
  • Classification accuracy tracking (predicted vs. actual resolution)
  • Alert on confidence drift (average confidence drops below threshold)
  • Response time tracking per tier
Calibration
The system gets smarter over time
  • Weekly review of classification accuracy by category
  • Confidence threshold adjustments based on false positive rate
  • New known-issue patterns added from resolved Tier 1 tickets
  • Quarterly prompt tuning based on accumulated feedback

Structured Logging

Every decision point in the system gets logged with full reasoning. When a ticket is classified, the log captures: the raw input, the Claude API response, the confidence score, which tier was selected, and why. When a response is generated, the log captures which knowledge base article was matched and what edits the support agent made (if any). This creates a complete audit trail for every ticket.

Calibration feedback loop

Tier 1 tickets that get resolved by support agents feed back into the known-issue database. Over time, more tickets qualify for Tier 0 auto-resolution. The system improves without manual prompt engineering.

Example 2: Event Follow-Up Automation (Make.com)

A 3-scenario system built for an events company handling venue enquiries. It processes 100+ enquiries per month with zero manual triage.

  • Scenario 1: MySQL poller detects new enquiries and triggers a follow-up email sequence.
  • Scenario 2: Reply detection watches for customer responses and stops the email sequence when someone replies.
  • Scenario 3: Scheduled escalation flags unresponsive leads for manual follow-up after the sequence completes.

Why it matters: This is the same webhook-to-classify-to-route-to-act pattern, built on a different orchestrator. The architectural decisions (event detection, conditional routing, escalation paths) transfer directly to the support agent system.
