TECHNICAL ARCHITECTURE

How the Pipeline Works

Four stages handle everything from lead discovery to email delivery. Each stage is an independent node group in n8n, so failures in one stage don't stop the others.

Architecture Overview

The workflow runs on a schedule you control. Apollo.io handles contact discovery, OpenAI handles research and writing, Instantly.ai handles sending. n8n ties it together and logs everything to Google Sheets. You only see the replies.

Stage 1: Lead Scraping

Apollo.io's People Search API is the entry point. You configure the filters once; the workflow runs them on every trigger.

  • People Search API with filters: job title, company size, industry, location
  • Data normalization: standardize names, validate email format, deduplicate against previous runs
  • Output per lead: name, email, title, company, domain, LinkedIn URL
  • Rate limiting: configurable delay between API calls to stay within Apollo plan limits
Contact data vs. email quality

Apollo.io provides the contact data. The AI personalization layer is what makes the emails worth opening. Most cold email tools stop at the data. This one starts there.

Stage 2: AI Research

Before writing a single word, the workflow researches each lead's company. This is what separates it from a mail merge.

  • OpenAI API call per lead, using the company domain as the anchor
  • Pulls key context: what the company does, their industry, approximate size, and any relevant positioning
  • Structures output as a JSON object so the email generation step can reference specific fields
  • Caches results by domain so the same company isn't researched twice in one batch

If the company website is unreachable or returns no useful content, the research step is skipped and the email generation step falls back to Apollo data only. The lead isn't dropped.

Stage 3: Email Generation

The email is built from a template with dynamic fields. The AI fills in the personalized parts; the structure stays consistent and on-brand.

  • Template fields: {{first_name}}, {{company}}, {{pain_point}}, {{personalized_opener}}
  • AI generates personalized_opener using the research data from Stage 2
  • Subject line generation: 2 to 3 variants per lead for A/B testing in Instantly
  • Output: a complete email object with all fields populated, ready to pass to Instantly.ai

You control the base template. The AI only touches the personalized opener and subject line. If you want a stricter template with less AI variation, that's a configuration change, not a rebuild.

Stage 4: Delivery

Instantly.ai's Campaign API receives the leads. Sending happens inside Instantly, so your warm-up schedules and sending limits stay intact.

  • Campaign API enrollment with all personalized fields mapped to Instantly variables
  • Sending schedule aligned with recipient timezone when Apollo provides it
  • Bounce handling: automatic removal from future sequences on hard bounce
  • Every enrolled lead is logged to Google Sheets with timestamp and campaign ID

Error Handling

Each stage has its own failure path. A bad email address in Stage 1 doesn't touch Stage 4. An OpenAI timeout in Stage 2 doesn't drop the lead.

Failure How It's Handled
Apollo API rate limit Exponential backoff, retry after delay
Invalid email from Apollo Validation filter catches it, lead logged and skipped
OpenAI API timeout Retry once, then fall back to template email without personalized opener
Instantly.ai rejection Logged with rejection reason, lead flagged for manual review
Company website unreachable Research step skipped, Apollo data used for email generation

Nothing in the workflow throws an unhandled exception that stops the whole run. Failures are logged to Google Sheets so you can review them without digging into n8n logs.
