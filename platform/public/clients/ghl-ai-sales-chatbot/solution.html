How Each Component Works

Eight components mapped to your eight requirements. Each section covers what it does, how it works technically, and why our approach is different.

1. AI Sales Conversations (Text + Voice)

The conversation engine is external to GHL. When a lead sends a message, GHL fires a webhook. n8n receives it, sends the message plus conversation history to the AI engine, gets a response, and sends it back via GHL's Conversations API.

Why external, not GHL's built-in bot

  • GHL Conversations AI trains on static Q&A and website content. It cannot follow a multi-step sales flow.
  • The external engine has a state machine tracking each prospect's position: cold open, rapport building, objection handling, close attempt, payment link sent.
  • Conversation memory: the AI reads the full conversation history before each response. It references what the prospect said 5 messages ago.
  • Objection library: predefined responses for common pushbacks ("too expensive," "need to think about it," "already tried credit repair," "is this a scam"). Not hardcoded responses – the AI adapts them to context.
How it works technically

GHL inbound message webhook → n8n receives → AI engine (Claude/OpenAI) generates response using conversation history + sales playbook + prospect profile → n8n sends reply via GHL Conversations API. Round trip: under 3 seconds for text.

2. Voice Capabilities

Three voice capabilities: outbound voice notes, inbound voice transcription, and optional live voice calls.

  • Outbound voice notes: AI generates text response → ElevenLabs converts to audio using cloned brand voice → hosted as MP3 → sent via Twilio MMS or GHL conversation.
  • Inbound voice transcription: Prospect sends voice message → Twilio transcribes → AI engine processes text → responds with text or voice note (configurable).
  • Live voice (optional): Twilio ConversationRelay with ElevenLabs as TTS provider. Real-time two-way conversation. Latency is 1-2 seconds per turn – acceptable for most sales calls, but not instant.
Honest limitation

Real-time voice has latency. The AI takes 1-2 seconds to respond, which is noticeable in a phone call. For most credit repair sales conversations, voice notes (not real-time calls) are more effective because they feel personal without the uncanny-valley pause. We recommend starting with voice notes and adding live voice once you validate the system works.

3. Multimedia Messaging

Context-triggered media delivery. The AI decides when to send proof, not on a fixed schedule.

  • When a prospect asks about results: send testimonial screenshot
  • When a prospect says "how does it work": send process infographic
  • When a prospect is in objection-handling: send before/after credit score screenshot
  • When a prospect asks "who are you": send brand introduction video

Media assets are configured per offer in the playbook. When you create a new client snapshot, you swap the media library – different testimonials, different branding, same trigger logic.

4. Automated Follow-Up System

Behavior-based, not time-based. Three categories of non-responders get different sequences.

No response (ghost)

  • Day 1: Casual check-in.
  • Day 3: Value hook (testimonial + voice note).
  • Day 7: Direct close attempt ("last chance" frame).
  • Day 14: Breakup message.

Clicked but did not buy

  • Day 1: Address the most common objection for the offer.
  • Day 3: Send social proof (screenshot of others who joined).
  • Day 5: Limited-time incentive if applicable.

Asked questions but did not convert

  • Day 1: Pick up where the conversation left off (AI reads the last exchange).
  • Day 3: New angle based on what they asked about.
  • Day 7: Direct close.

n8n tracks each prospect's behavior state via GHL tags and custom fields. Each follow-up is AI-generated and personalized, not a template blast.

Personalized, not generic

Every follow-up message is generated by the AI engine using the prospect's conversation history. If they asked about pricing, the follow-up addresses pricing. If they asked about results, it sends proof. The AI does not just wait and resend the same message.

5. Sales and Conversion Tracking

Detect when a user purchases, books, or joins. Automatically stop sales messaging and start onboarding.

  • GHL pipeline stage change webhook fires when prospect moves to "Purchased" or "Booked" or "Joined Community"
  • n8n processes the event: removes prospect from follow-up sequences, updates tags, triggers onboarding workflow
  • Onboarding workflow: welcome message, next steps, community access instructions
  • Activity log: every touchpoint (message sent, message received, voice note sent, link clicked, purchase detected) is logged per lead
No awkward overlap

The worst thing a sales bot can do is keep selling after someone already bought. Pipeline-based detection ensures the moment a prospect converts, the system switches from sales mode to onboarding mode. Automatic, no manual intervention.

6. GoHighLevel Integration

Built on GHL API v2 and webhooks. Everything that can be programmatic, is.

API-driven (automatable)

  • Contact create/update/search with custom fields and tags
  • Conversations: send messages, read history (text, SMS, email, web chat)
  • Pipeline: create/move opportunities through stages
  • Tags: apply/remove based on conversation state
  • Custom values: store AI engine state, conversation summaries, behavior flags

Workflow-driven (one-time UI setup)

  • GHL workflows for initial routing (which conversation channel → which webhook)
  • Conversations AI disabled for contacts the AI engine is handling (workflow action)
  • Pipeline stage change triggers (webhook to n8n)

The one-time UI work (workflow setup) is captured in the GHL snapshot. Once built, it clones automatically to every new sub-account.

7. Snapshot System

Two-part cloning: GHL snapshot for CRM config, provisioning script for external stack.

GHL snapshot captures

  • Pipelines, stages, custom fields, tags
  • Workflows (routing, stage triggers, onboarding)
  • Conversation channels configuration
  • Email/SMS templates

Provisioning script handles

  • New Twilio phone number assignment
  • ElevenLabs voice persona (clone from recording or select preset)
  • n8n webhook URLs updated for new sub-account
  • AI engine: swap brand voice config, offer details, media library, sales playbook
  • Test message sent to verify end-to-end flow

New client deployment: apply GHL snapshot to new sub-account (API or UI), run provisioning script (5-10 minutes), send test message. Total setup time per new client: under 30 minutes once the template exists.

Scalable from day one

Each new client clone costs roughly $200-300 to provision (mostly the time to customize the sales playbook and media library for the new offer). The infrastructure is reusable. The playbook content is what changes per client.

8. AI Training / Prompt Engineering

The AI is only as good as its playbook. Three layers of prompt engineering.

Layer 1 – System prompt

Brand personality, tone rules, conversation boundaries (what the AI will and will not say), compliance guardrails for credit repair industry.

Layer 2 – Sales playbook

The full sales flow as structured instructions. Opening hook, rapport building, qualification questions, offer presentation, objection handling (10-15 common objections with response strategies), close attempts, payment link delivery.

Layer 3 – Niche adaptation

Per-client customization layer. Swap the offer details, pricing, testimonials, and objection responses. The sales flow structure stays the same – what changes is the product-specific content.

When you want to adapt the system for a different niche (not credit repair), you rewrite Layer 3 and update the media library. Layers 1 and 2 stay mostly intact because the sales psychology is the same.

Adjustable without code changes

The sales playbook, objection library, and brand voice settings are configuration, not code. You can update objection responses, add new qualification questions, or change the tone without touching the AI engine. We document exactly where each setting lives.
