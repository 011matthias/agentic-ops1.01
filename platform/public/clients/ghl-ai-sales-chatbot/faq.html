Pricing

Why $3,500 when the budget is $2,500? +

Scope. This is 8 major components across a 3-4 week build: AI conversation engine, voice pipeline, multimedia messaging, behavior-based follow-ups, conversion tracking, GHL integration, snapshot system for client cloning, and AI prompt engineering. Each of these is a real deliverable, not a checkbox. $3,500 is what it costs to build all of them to production quality.

At $2,500 we would need to cut components. The most likely cuts: voice capabilities (no ElevenLabs, no voice notes), simplified follow-ups (time-based delays instead of behavior-based), and no provisioning script for the snapshot system (manual setup per client instead of automated). Those cuts save $1,000 but remove the features that make this system actually different from a basic GHL chatbot.

We would rather be direct about the scope than deliver a reduced system that does not match your brief.

Can you do the work at $2,500 with reduced scope? +

Yes, but it is a different product. At $2,500, we would deliver: AI conversation engine (text only, no voice), GHL integration, follow-up sequences (time-based, not behavior-based), conversion tracking, and a basic snapshot (GHL only, no provisioning script).

What you lose: voice notes, multimedia messaging, behavior-based follow-ups, and automated client cloning. The snapshot would require manual provisioning for each new client instead of a one-command script.

If budget is fixed at $2,500, we can discuss this reduced scope. But given that you want "one of the most advanced AI sales systems in this space," the full scope at $3,500 is what delivers that.

How is payment structured? +

Via Upwork milestones. Milestone 1: $1,750 to start (covers Foundation + AI Brain, Phases 1-2). Milestone 2: $1,750 on delivery (covers Voice + Follow-ups + Snapshot, Phases 3-5). Standard Upwork escrow protects both parties.

No payment until we start. No final payment until you have a working system with documentation in your hands.

Technical

Why an external AI brain instead of GHL's Conversations AI? +

GHL's Conversations AI trains on static content -- URLs, documents, Q&A pairs. It is designed for FAQ-style responses and appointment booking. It cannot follow a multi-step sales flow, handle objections adaptively, or maintain conversation state across messages.

The external AI brain has a sales playbook, a conversation state machine (tracking where each prospect is in the sales flow), and full conversation memory. When a prospect says "that is too expensive," it does not freeze -- it runs the price objection handling flow from the playbook.

For credit repair sales, this distinction matters. Your prospects have real objections ("I already tried credit repair," "how do I know this works," "I cannot afford it right now"). A FAQ bot answers questions. A sales agent handles objections and guides toward a close. That is the difference.

Can this work with GPT instead of Claude? +

Yes. The AI engine is model-agnostic. We default to Claude because it follows structured instructions precisely, which matters for reliable sales flow execution. GPT-4 also works well. If you have an existing OpenAI account or preference, we adapt the prompts accordingly. The system architecture does not change.

How does the voice cloning work? +

ElevenLabs voice cloning takes a 60-second recording of the brand owner speaking naturally. From that, it generates a voice model that can speak any text in that voice. Quality is good enough that most prospects cannot tell it is AI-generated, especially in a voice note format.

If you do not want to clone a real voice, ElevenLabs has high-quality preset voices. We can select one that matches the brand personality. Either approach works -- the system architecture is the same.

What if the AI says something wrong or inappropriate? +

Three safety layers. First, the system prompt has compliance guardrails -- topics the AI will not engage on, claims it will not make, and language it will not use. For credit repair, this includes not guaranteeing specific credit score improvements or making claims that violate FTC guidelines.

Second, a confidence threshold. If the AI engine scores below 80% confidence on its response, the message routes to a human review queue instead of sending automatically. This catches ambiguous situations.

Third, the conversation state machine has explicit boundaries. The AI cannot skip stages (it will not send a payment link before qualifying the prospect) and it will not respond to messages that look like they are from a minor or contain certain flagged content.

Delivery

Can you deliver in 3-4 weeks? +

Yes, if the prerequisites are ready on time. The timeline is realistic because we have built similar AI conversation systems before. We are not figuring out the GHL API or ElevenLabs integration for the first time on your project.

The main risk to the timeline is delayed input: if the sales playbook content (your current scripts, objection notes, brand voice recording) takes longer than expected to gather, that pushes the AI brain phase. The onboarding form asks for everything we need upfront.

What happens if something breaks after delivery? +

The maintenance guide covers the most common scenarios: AI response quality drift (re-tune prompts), API key expiry, Twilio number issues, GHL webhook disconnection. Most issues are fixable by following the guide.

For anything the guide does not cover, post-delivery support can be arranged separately. The n8n workflows and AI configuration are fully documented and exportable. Any automation developer can pick them up.

Do I need technical skills to manage this? +

Day-to-day operation: no. The system runs autonomously. When someone converts, it stops selling and starts onboarding. When someone goes cold, it follows up automatically.

For changes: updating the sales playbook (adding new objections, changing the tone) requires editing prompt text, which is non-technical. Changing GHL pipeline stages or adding new follow-up sequences requires n8n workflow editing, which is visual (drag-and-drop) but does require some familiarity with n8n.

Risk + Limitations

What are the honest limitations? +

Three limitations to be aware of:

1) Real-time voice calls have latency. The AI takes 1-2 seconds to respond in a live call, which is noticeable. Voice notes work great because the prospect does not expect an instant response. Live calls are possible but not as smooth as a human call. We recommend starting with voice notes.

2) GHL workflow creation is not API-accessible. We build the workflows manually in GHL's visual builder, then capture them in the snapshot. Any per-client workflow customization requires UI access. The AI brain and orchestration layer are fully API-driven, but GHL's workflow builder is not.

3) The AI is not perfect. It handles 85-90% of conversations well out of the box. The remaining 10-15% are edge cases that need human review. The confidence threshold routes these to a queue. Over time, the playbook gets tuned and the percentage improves.

What about data security? +

All API keys stored in n8n's encrypted credentials vault or GHL's native credential storage. Conversation data flows through your own infrastructure (GHL + n8n). The only external service processing conversation content is the AI provider (Anthropic or OpenAI). Both have enterprise data policies -- API usage is not used for model training by default.

We do not retain access to your GHL account, n8n instance, or any credentials after delivery. Everything is in your hands.

What is the risk if we proceed? +

Main risks: timeline slippage if prerequisites are delayed (mitigated by the onboarding form), and AI quality not matching expectations (mitigated by the tuning phase with real conversations and the confidence threshold for human escalation).

Financial risk is structured via Upwork milestones. You do not release the final $1,750 until the system is working. If we fail to deliver, you keep the funds via Upwork's dispute process.

The risk of not building this: continuing to scale your credit repair agency with manual sales conversations or basic template bots that do not convert. The snapshot system means you only build once. Every client after that is a clone.
