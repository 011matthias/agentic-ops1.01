System Architecture

Two independent systems sharing a common infrastructure layer. Each can operate on its own, but together they give your team both automated email intelligence and an internal AI assistant.

System 1: Email Compliance Monitor

  • M365/Gmail event subscription
  • Pre-processing + PII stripping
  • Claude API analysis (zero retention)
  • Severity-based alert routing
  • Automated retention lifecycle

System 2: AI Chat Interface

  • Open WebUI (self-hosted on AWS)
  • Staff authentication + roles
  • Anthropic Claude API backend
  • Per-user conversation history
  • Usage tracking + cost controls

Shared Infrastructure

  • AWS hosting (EC2/ECS + supporting services)
  • CloudWatch monitoring + billing alerts
  • Retry logic + dead letter queue
  • GDPR compliance layer (DPIA, audit trail, retention automation)

Email Processing Flow

Here's exactly what happens when an email arrives in the monitored mailbox, step by step.

New Email → Event Webhook → Extract Body → Strip PII → Claude Analysis → Score + Tag → Route by Severity → Store + Alert

Step-by-step breakdown

  1. New Email arrives -- Microsoft Graph or Gmail API sends a push notification to your AWS endpoint. No polling, no delay.
  2. Event Webhook receives -- Lambda function (or container) picks up the event, validates the signature, and fetches the email content.
  3. Extract Body -- HTML is parsed to plain text. Attachments are noted but not processed (configurable). Headers are extracted for metadata.
  4. Strip PII -- Names, phone numbers, email addresses, and other identifiable data are masked before the content reaches the AI. Original is stored separately under access controls.
  5. Claude Analysis -- Sanitized content is sent to Anthropic's API with zero-retention enabled. Claude returns sentiment, complaint detection, tags, severity, and recommended action.
  6. Score + Tag -- The AI output is validated and normalized. Confidence scores below your threshold are flagged for manual review instead of auto-routing.
  7. Route by Severity -- Severity 4-5 triggers immediate alerts. Severity 3 goes to the daily digest queue. Severity 1-2 is logged silently.
  8. Store + Alert -- Results land in your data store with the full audit trail. Alerts fire to Slack and/or email based on your configuration.
End-to-end latency

From email arrival to alert delivery: typically under 30 seconds. The Claude API call is the longest step (~2-5 seconds). Everything else is sub-second.

Key GDPR note

The Anthropic API zero-retention setting means email content is processed and returned but never stored on Anthropic's servers. This is critical for the UK-to-US data transfer analysis -- the data transits through US infrastructure but isn't retained there.

Lifecycle compliance notes

  • Capture: Only business email addresses are monitored. Personal accounts are excluded by design.
  • Minimize: Data minimization happens before AI processing. The AI never sees raw PII unless explicitly configured to (e.g., for name-based complaint tracking).
  • Process: Anthropic's zero-retention API means no data persistence on their infrastructure. The transfer is documented in the DPIA.
  • Store: All stored data is encrypted at rest (AES-256) and in transit (TLS 1.2+). Access requires authenticated AWS credentials with role-based permissions.
  • Archive: After the active retention period, data moves to S3 Glacier or equivalent cold storage. Still accessible for audit purposes, but not for active queries.
  • Purge: Automated permanent deletion. The audit trail records that deletion happened, but the data itself is irrecoverable. This satisfies the right to erasure requirements.
