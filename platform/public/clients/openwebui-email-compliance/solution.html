Email Monitor Pipeline

The email monitoring system is the core deliverable. It captures incoming emails, runs them through AI analysis, and routes the results to the right place -- all without manual intervention.

Email Source (M365/Gmail) → Pre-Processing → Claude Analysis → Severity Router → Storage + Alerts

Email Source (M365/Gmail)

Event-driven ingestion via Microsoft Graph API or Gmail API. New emails trigger processing automatically -- no polling intervals, no missed messages. The system subscribes to mailbox changes and receives push notifications when new emails arrive.

Pre-Processing

Before any email reaches the AI, it goes through a data minimization step. PII is stripped or masked, email headers are parsed for metadata, and the content is normalized into a standard format. This reduces GDPR exposure and keeps API costs down by sending only what's needed.

Claude Analysis

The core intelligence layer. Anthropic's Claude API analyzes each email for sentiment, complaint indicators, legal risk markers, and urgency signals. The API is configured for zero data retention -- nothing is stored on Anthropic's servers after processing.

Severity Router

Based on the AI analysis, each email gets a severity score (1-5) and is routed accordingly. High-severity items trigger immediate alerts. Low-severity items are logged for daily digests. The routing logic is configurable -- you can adjust thresholds without touching code.

Storage + Alerts

Results land in your chosen data store with full audit trail. Alert channels (Slack, email, or both) are configured per severity level. Retention automation handles archival and purging on your defined schedule.

AI Processing

Here's what Claude extracts from each email that passes through the system.

Analysis Output Fields

  • Sentiment: positive, neutral, or negative
  • Complaint detection: yes/no with confidence score (0-100%)
  • Key tags: complaint, urgent, legal risk, escalation, cancellation
  • Severity score: 1 (informational) to 5 (critical)
  • Suggested priority action: what to do next, based on the analysis

Alert System

Not every email needs someone's immediate attention. The alert system routes based on severity so your team only gets interrupted when it matters.

Severity 4-5: Immediate Alert

Legal threats, high-confidence complaints, and urgent escalations trigger instant notifications. These go to your designated response team via Slack and email simultaneously. Average time from email receipt to alert: under 30 seconds.

Severity 3: Daily Digest

Moderate-concern items -- confirmed complaints without urgency markers, cancellation requests, negative sentiment patterns. These are batched into a daily summary sent at your chosen time. Enough visibility without notification fatigue.

Severity 1-2: Logged, No Alert

Routine emails, positive feedback, and standard inquiries. Fully analyzed and stored for reporting, but they won't generate any notifications. Available in the dashboard for trend analysis and audit purposes.

Configurable thresholds

All severity thresholds, alert channels, and digest timing are adjustable through configuration. No code changes required to tune the system to your team's needs.

AI Chat System

The second system: a self-hosted AI chat interface for your team, running on your own infrastructure.

Open WebUI on AWS

Open WebUI is a mature, open-source chat interface. We'll deploy it on AWS (EC2 or ECS depending on your scale preference) with Docker. Your data stays on your servers -- no third-party SaaS dependency for the chat layer.

Staff Authentication

Managed user accounts with role-based access. Options include local authentication (built into Open WebUI) or SSO integration with your existing identity provider. Each user gets their own conversation history, isolated from other users.

Anthropic API with Zero Retention

The chat connects to Anthropic's Claude API configured with zero data retention. Conversations are processed and returned but never stored on Anthropic's infrastructure. Combined with your self-hosted deployment, this gives you full control over where data lives.

Cost control built in

CloudWatch billing alerts notify you before API costs exceed your set threshold. Usage dashboards show per-user and per-department consumption so you can allocate costs accurately.

GDPR Compliance Layer

This isn't a separate feature -- it's woven into both systems. Here's what the compliance layer covers.

Pre-Processing Data Minimization

Before any email content reaches the AI, PII is identified and stripped. Only the fields necessary for analysis are sent to the API. Original emails are stored separately with access controls, so the AI never processes more data than it needs.

Anthropic API Zero Retention

Anthropic offers a zero-retention API configuration. We'll set this up so that email content sent for analysis is processed and discarded -- never used for model training, never stored beyond the request lifecycle. This is documented in Anthropic's data processing terms.

Retention Automation Engine

Configurable retention policies with two stages: archive (move to cold storage after X days) and purge (permanent deletion after Y days). Both stages are automated -- no manual cleanup required. Every action is logged to the audit trail.

Audit Trail

Every data access, processing event, and retention action is logged. When your compliance team needs to demonstrate what happened to a specific email's data, the trail shows exactly when it was processed, what was extracted, when it was archived, and when it was purged.

Shared Infrastructure

Both systems share a common infrastructure layer designed for reliability and observability.

Event-Based Architecture

No polling scripts. The email monitor uses push-based event subscriptions (Microsoft Graph webhooks or Gmail push notifications). The chat system responds to user requests in real time. Events are queued and processed asynchronously, so spikes in volume don't cause failures.

Retry Logic with Exponential Backoff

When an API call fails (Anthropic rate limit, transient network error, temporary service outage), the system retries automatically. Each retry waits longer than the last. After max retries, the item moves to the dead letter queue for manual review -- it's never silently dropped.

CloudWatch Monitoring + Billing Alerts

Dashboards for processing volume, error rates, API latency, and costs. Billing alerts trigger before you hit your budget ceiling. Anomaly detection flags unusual patterns -- a sudden spike in high-severity emails, an unexpected drop in processing volume, or API costs trending above normal.

Dead Letter Queue

Failed processing attempts land in a dead letter queue instead of being lost. Each item includes the original payload, the error details, and the number of retry attempts. You can reprocess items manually or set up automated replay once the underlying issue is resolved.
