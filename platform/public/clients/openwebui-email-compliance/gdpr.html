GDPR Compliance Architecture

How every component of this system is designed with UK GDPR requirements from the ground up -- not bolted on after the fact.

Why GDPR Matters Here

This isn't optional

A 100+ person UK company processing customer and staff emails through AI isn't a standard integration project. It's a data processing operation with specific legal requirements:

  • Email content is personal data under UK GDPR
  • Automated analysis constitutes 'processing' under Article 4
  • AI-based complaint flagging may constitute 'automated decision-making' under Article 22
  • Sending data to Anthropic's US servers is an international transfer requiring legal basis
  • Retaining processed email data without lifecycle management accumulates liability

Every technical decision in this system flows from these requirements.

Key design decision

AI analysis results (sentiment scores, tags, severity) are stored. Raw email content is NOT stored by default -- only references and metadata. This is data minimization in practice.

Data Minimization

Here's what happens at each stage of the pre-processing pipeline:

1
Email arrives from M365/Gmail
2
Attachments stripped (not processed by AI)
3
Headers minimized (only sender, subject, timestamp retained)
4
Body text extracted for AI analysis
5
AI processes text, returns structured output
6
Structured output stored; raw text discarded (configurable)

At each stage, we're asking: "Do we need this data?" If not, it doesn't enter the pipeline.

International Transfers

Anthropic's Claude API is hosted in the US. Sending email content to their API for analysis constitutes an international transfer under UK GDPR.

Here's how we handle it:

  1. Anthropic API configured for zero data retention (data transits servers, isn't stored)
  2. Standard Contractual Clauses (SCCs) documentation prepared
  3. Transfer Impact Assessment (TIA) included in DPIA
  4. Data minimization applied before transfer (only necessary text sent)
Anthropic's position

Anthropic's API terms explicitly support zero-retention mode for API calls. Data sent via the API is not used for model training and is not stored after processing. This is documented in their data processing agreements.

Rights and Requests

Here's how the system supports GDPR data subject rights:

Right How It's Supported
Right of access (SAR) Structured data, searchable by email address or sender
Right to erasure Manual purge capability for specific records
Right to restrict processing Email sources can be excluded from pipeline
Right to object Automated processing can be paused per sender/domain
Right not to be subject to automated decisions Human review queue for high-severity flags

The human review queue for severity 4-5 alerts is a design feature, not a limitation. It ensures that no critical decision about a complaint is made purely by AI.

DPIA Overview

A Data Processing Impact Assessment is required for this system. We'll provide a completed template as part of Phase 1.

The DPIA covers:

  1. Description of processing operations
  2. Assessment of necessity and proportionality
  3. Assessment of risks to data subjects
  4. Measures to address risks (technical and organizational)

The DPIA covers both the email monitoring pipeline and the AI chat interface. It's designed for your DPO or compliance team to review and sign off.
