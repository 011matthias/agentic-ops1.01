Technical

2 How do you handle the webhook URL transition?

Webhook cutovers are the highest-risk part of any Make.com migration. A new Make.com account means new webhook URLs, and anything that fires events at those URLs (Hero Software, LexOffice, external services) needs to be updated at the same moment the new scenario goes live.

The process is coordinated, not improvised. Before any cutover happens:

  • The new scenario is built and tested with real data in a non-production context
  • We schedule a cutover window with your sysadmin, outside peak business hours
  • The new webhook URL is registered in the source system
  • The old scenario stays active until the first successful event is confirmed in the new one

For scenarios where parallel operation isn't possible (e.g., a webhook that triggers a unique action), the window is kept as short as possible and monitored in real time. No events get dropped because we don't decommission the old scenario until the new one has proven itself.

3 What if a scenario breaks during migration?

The migration is designed so that a break in the new account doesn't affect your live operations. The old account stays active until each scenario is fully validated in the new one. That's the whole point of the parallel validation phase in week 4.

If something breaks during the migration build (before any cutover), it gets fixed before cutover is scheduled. If something breaks after a cutover, the rollback path is the same: the old scenario is still there, still configured, and can be re-enabled while the issue is diagnosed.

What I don't do is a big-bang migration where everything moves at once and you're on the new account before anything is verified. Every scenario group gets its own validation cycle before the old one is turned off.

6 How do you handle LexOffice's API rate limits?

LexOffice's API enforces a 2 requests per second limit. That's easy to hit if a scenario is processing a batch of invoices or contacts without any pacing built in.

The approach is straightforward: scenarios that call LexOffice in bulk are built with queue-based processing rather than parallel execution. Each item goes through sequentially with appropriate spacing. For scenarios that hit the limit unexpectedly, retry logic handles the 429 response automatically, with exponential backoff so a burst doesn't cascade into repeated failures.

This is built into the scenario design from the start, not patched in after a rate limit error surfaces in production.

5 What happens after the migration is done?

Once the migration is complete and the old account is decommissioned, the engagement shifts to ongoing maintenance. There's no retainer requirement unless you want one. Hours are billed at actual usage.

What that typically covers:

  • Change requests: A field mapping changes in Hero Software, LexOffice updates an API endpoint, you want to add a new notification. These are usually small, scoped, and quoted before work starts.
  • New scenario builds: If you want to automate something that isn't currently automated, new builds follow the same methodology as the migration: design, test, document, monitor.
  • Ongoing monitoring: Error alerts are configured during the migration phase. If a critical scenario fails, you'll know about it before a customer does.

Some months will be quiet. You won't be billed for hours that weren't worked.

7 Can you build new scenarios too, or just migrate existing ones?

Both. The migration gets your existing infrastructure onto a stable foundation. Once that's done, new builds are a natural extension of the same work.

New scenarios follow the same process: requirements discussion, design, test with real or representative data, documentation, and monitoring setup. The advantage at that point is that I already know your systems. A new automation connecting Hero Software to LexOffice doesn't require any discovery on my end.

If there are automations you've been wanting to build but haven't had the capacity for, the post-migration phase is a good time to scope them. The infrastructure will be clean, documented, and in one place.
