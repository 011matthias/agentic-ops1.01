How this timeline works

Each phase ends with a deliverable you can review before the next one starts. If something unexpected turns up during the audit, we talk before continuing. Nothing happens in the background without your sign-off.

Week 1: Audit and Discovery

Before touching a single scenario, we need a complete picture of what exists. This week is read-only investigation. Nothing gets changed in your current account.

Week 1
Audit and Discovery
Read-only investigation. No changes to your live account.
Days 1-2

Account access and blueprint export

  • Get read access to your current Make.com organisation
  • Export all scenario blueprints as JSON
  • Catalogue every active, inactive, and paused scenario
  • Note which scenarios are currently running on a schedule versus webhook trigger
Days 3-4

Dependency mapping and connection audit

  • Trace which scenarios depend on output from other scenarios
  • Document every external connection: Hero API, LexOffice API, Mailgun, OpenAI, S3
  • Identify webhook URLs that are registered in third-party systems
  • Flag any custom apps, data stores, or shared variables
  • Note authentication types (API key, OAuth, basic auth) for each connection
Day 5

Deliverable preparation and risk review

  • Compile the scenario inventory spreadsheet with status, trigger type, and system dependencies per scenario
  • Build the dependency map showing which scenarios must be migrated together
  • Flag high-risk items: webhook URLs that need coordinated cutover, OAuth connections requiring re-authorisation
  • Propose the migration order for Weeks 2-3 based on findings
📄
Week 1 Deliverable
Scenario inventory spreadsheet and dependency map. Shared with you before Week 2 starts.
Why the audit comes first

Migrating without a dependency map means discovering mid-way that scenario B feeds scenario C, which means scenario C breaks the moment B's webhook URL changes. The audit week prevents exactly that kind of cascading failure.

Weeks 2-3: Phased Migration

Migration runs in two waves, ordered by dependency complexity. Independent scenarios go first so we can validate them cleanly before touching anything with cross-scenario dependencies.

Week 2
Independent Scenarios
Re-create, reconnect, validate. No webhook cutovers yet.
Days 1-2

Migrate standalone scenarios

  • Re-create each independent scenario in the new Make.com account using exported blueprints
  • Preserve original logic exactly. No refactoring at this stage.
  • Set all migrated scenarios to inactive until testing is complete
Days 3-4

Re-establish API connections

  • Re-authenticate the Hero Software API connection using your credentials
  • Re-authenticate the LexOffice API connection
  • Configure Mailgun connection with sending domain and API key
  • Set up OpenAI API connection
  • Configure S3 bucket access with your credentials
  • Run a test execution on each standalone scenario to confirm data flows correctly
Day 5

Validate and document Week 2 progress

  • Confirm all standalone scenarios pass test runs
  • Update the migration tracker with status per scenario
  • Brief update to you on what's done and what's coming in Week 3
Week 3
Dependent Scenarios and Cutover
Coordinated webhook updates with your sysadmin.
Days 1-2

Migrate dependent scenario chains

  • Re-create scenarios that consume output from other scenarios
  • Wire up internal scenario-to-scenario connections in the new account
  • Test full chain execution end-to-end with sample data
Days 3-4

Webhook URL cutover windows

  • Schedule cutover windows with your sysadmin for each system that has a registered webhook
  • Update Hero Software to point to the new Make.com webhook URLs
  • Update any other third-party systems with changed URLs
  • Confirm incoming test events are received correctly in the new account
  • Activate migrated scenarios and deactivate the corresponding old ones
Day 5

Full migration review

  • Confirm every scenario is active in the new account
  • Confirm no scenarios remain active in the old account
  • Review execution logs for any errors in the first 24 hours
✅
Weeks 2-3 Deliverable
All scenarios live in the new account. Old account fully deactivated. Migration tracker showing 100% completion.

Week 4: Stabilization

Going live isn't the finish line. This week catches anything that only surfaces under real production load: timing edge cases, data formatting differences, and any webhooks that weren't updated during cutover.

Week 4
Stabilization
Monitor, harden, document. Then hand over.
Days 1-2

Parallel run period

  • Keep old account accessible (but inactive) as a reference during this window
  • Monitor new account execution logs for errors or unexpected behavior
  • Compare output data from new scenarios against expected results
  • Fix any issues found immediately, same day where possible
Days 3-4

Error monitoring and alert routing

  • Configure Make.com error notifications to route to your team's inbox or Slack
  • Set up alert thresholds for execution failures
  • Test that alerts fire correctly by triggering a known error condition
  • Document the alert routing so your team knows what to do when one arrives
Day 5

Documentation handover

  • Finalize the scenario reference document: purpose, trigger, connected systems, and data flow for each scenario
  • Document all API connection details (without credentials) so your team knows what's connected where
  • Note any operational quirks discovered during migration
  • Walk your team through the new account structure in a short video or call
🔒
Week 4 Deliverable
Production-ready system with monitoring configured and full documentation in your hands.

Week 5+: Ongoing Maintenance

After stabilization, the engagement shifts to a steady-state maintenance model. Hours flex up or down based on what you actually need each month, not a fixed retainer.

Week 5+
Ongoing Maintenance
Flexible hours. Adjusted monthly to match actual workload.
Change requests
  • Scenario edits when your processes change
  • New system integrations as your stack grows
  • Field mapping updates when APIs change on the Hero or LexOffice side
Monitoring
  • Weekly review of execution logs and error rates
  • Proactive fixes before issues affect your operations
  • Make.com platform updates that affect your scenarios
New builds
  • Build additional scenarios when new automation needs come up
  • Same rate, same account, no new setup required
  • Priority turnaround for anything business-critical
Hours

Hours are billed as worked. In a quiet month, it might be 2-3 hours. In a month with new builds or a major system change, it could be 10-15. No minimum commitment.
