Tool Choices

1 Why axe-core and not WAVE API or Lighthouse?

You chose axe-core, and it's a solid choice. axe-core runs inside the page DOM via Puppeteer, which means it catches violations that external API-based tools miss -- dynamic content, JavaScript-rendered elements, and interactive components. It's also open source, so there are no per-scan API costs. The WCAG 2.1 AA ruleset is well-maintained by Deque Systems.

2 Can I swap Instantly.ai for another email tool later?

The workflow is built for Instantly.ai's API endpoints specifically, as you requested. If you wanted to switch to a different tool in the future, the integration layer (HTTP Request node in n8n) would need to be reconfigured for the new tool's API. It's doable but isn't a drop-in swap -- the API payloads and authentication differ between platforms.

3 Why n8n instead of Make or Zapier?

Because you asked for it, and it's the right call for this use case. n8n runs self-hosted on your own server, which means no per-execution costs, full control over the workflow, and no third-party platform holding your automation hostage. For a batch job processing 500 URLs, the self-hosted model avoids the per-operation pricing that Make or Zapier would charge.

Hosting

4 Will Puppeteer actually run on NameHero shared hosting?

This is the biggest technical risk in the project. Shared hosting typically restricts long-running processes and headless browser execution. I'll verify this during Phase 1 (Days 1-2) before any workflow work begins. If NameHero's server can't run Puppeteer reliably, the fallback is to offload just the auditing step to a cloud function (AWS Lambda or Google Cloud Function). n8n still orchestrates everything from NameHero -- the cloud function handles only the CPU-intensive browser work. This adds a small per-URL cost (roughly $0.001-0.005 per URL) but keeps the pipeline reliable.

5 What if NameHero blocks n8n or Node.js processes?

Some shared hosting providers restrict persistent Node.js processes. If NameHero doesn't support PM2 or background Node.js, the alternative is running n8n in a lightweight VPS (like a $5/month DigitalOcean droplet) that connects to your NameHero-hosted data. I'll test this on day one and flag it immediately if it's an issue -- no surprises mid-project.

6 Do I need SSH access or just cPanel?

SSH access is strongly preferred for installing n8n and Puppeteer. If only cPanel terminal is available, it's workable but more limited. I'll need your NameHero credentials during onboarding to assess what's possible on your specific plan.

Scale & Reliability

7 Can it really handle 500 URLs in one run?

Yes. At 2-4 seconds per URL (your own estimate, which is accurate for axe-core), 500 URLs takes 20-30 minutes. The workflow processes URLs sequentially with batch writes to Google Sheets every 10-20 rows to avoid rate limits. Memory usage stays flat because each URL is processed and discarded before the next one starts.

8 What happens when a site blocks the headless browser?

Three layers of defense. First, user-agent rotation so the browser doesn't look like a bot. Second, puppeteer-extra-plugin-stealth to bypass common detection scripts. Third, if both fail, the URL is logged as BLOCKED in the sheet, the error reason is recorded, and the pipeline moves to the next row. It never stops the run.

9 What if my Google Sheet has more than 500 rows?

The workflow can process larger batches. The 500-URL target is about single-run duration (30 minutes). For larger lists, the simplest approach is a scheduled trigger that processes in chunks -- 500 per run, multiple runs per day. The sheet tracks which rows have been processed so nothing gets audited twice.
