How the Pipeline Works

Five components working together: n8n orchestration, axe-core auditing, Google Sheets data layer, Instantly.ai email trigger, and error handling at every step.

n8n Self-Hosting on NameHero

n8n runs on your NameHero server, which means the workflow data stays in your environment. There's no third-party cloud cost for n8n itself -- you own the instance.

1
SSH access to NameHero server
Node.js 18+ required. I'll verify the Node version during setup and install or request an upgrade if needed.
↓
2
n8n installed via npm, configured with PM2
PM2 keeps n8n running as a background process and restarts it automatically if the server reboots.
↓
3
Reverse proxy via .htaccess or subdomain
Exposes the n8n web UI at a URL on your domain so you can access the workflow editor without SSH.
↓
4
SSL certificate configured
NameHero includes Let's Encrypt SSL. I'll configure it for the n8n subdomain so the web UI is served over HTTPS.
SHARED HOSTING CAVEAT

NameHero Silver NVMe is shared hosting. Running headless Chrome (Puppeteer) on shared hosting can hit process limits or be restricted by the hosting provider. I'll test this during setup (Days 1-2). If the server can't run Puppeteer reliably, the fallback is a lightweight cloud function (AWS Lambda or Google Cloud Function) that handles just the auditing step, with n8n still orchestrating everything else from NameHero. This adds a small per-URL cost but keeps the architecture clean.

axe-core Audit Engine

axe-core is the industry-standard open-source accessibility testing library. It's what most accessibility auditing tools are built on top of -- I'm using it directly so you get the full ruleset without a markup layer in between.

1
n8n Code node launches Puppeteer in headless mode
Puppeteer spins up a headless Chrome instance for each URL. It's the same engine as a real browser.
↓
2
Navigates to target URL with 15-second timeout
If the page doesn't load within 15 seconds, the URL is marked as TIMEOUT and the pipeline moves on.
↓
3
Injects axe-core library into the page DOM
axe-core is loaded into the live page context so it can analyze the actual rendered DOM, not just the raw HTML source.
↓
4
Runs WCAG 2.1 AA ruleset analysis
axe-core tests the page against the full WCAG 2.1 AA standard. It checks color contrast, image alt text, form labels, ARIA usage, keyboard navigation, and more.
↓
5
Captures violation array: rule ID, impact level, affected elements
Each violation includes the rule ID (e.g. color-contrast), impact level (critical/serious/moderate/minor), and the specific DOM elements that failed.
↓
6
Returns structured results to n8n for processing
The Code node returns a clean object: pass/fail status, total violation count, and the top 3 violation types by frequency. n8n takes it from there.

Bot Detection Handling

Some sites block headless browsers. The engine has three layers of protection to reduce blocks and handle them gracefully when they happen.

🌐
User-Agent Rotation
  • Randomized user-agent strings
  • Avoids pattern-based blocking
  • Different browser signatures per request
👔
Stealth Mode
  • puppeteer-extra-plugin-stealth
  • Bypasses common bot detection
  • Handles JavaScript challenges
📚
Graceful Fallback
  • 15-second timeout per URL
  • Blocked sites marked "unable to audit"
  • Error logged with reason
  • Pipeline continues to next URL

Results Processing

For each URL, the workflow writes results back to the same row in your Google Sheet. Pass means zero WCAG 2.1 AA violations were detected. Fail includes the total error count and the top 3 error types by frequency -- so you can see at a glance what the most common issues are across your prospect list.

The sheet updates in place. No duplicate rows, no separate output sheet -- the status column and audit columns update on the same row as the input data.

Instantly.ai Email Integration

Failed audits are the only URLs that trigger outreach. The IF node in n8n checks the audit status and routes FAIL rows to the Instantly.ai API. Pass, blocked, and timeout rows are skipped entirely -- your outreach list stays clean.

1
IF node checks audit status (FAIL only)
Any status other than FAIL is filtered out at this step. Only confirmed accessibility failures get sent to Instantly.
↓
2
Maps contact email, company name, audit summary to Instantly API payload
The payload includes the recipient's email, company name, error count, and top violation type. These can be used as merge fields in your Instantly email template.
↓
3
POST to Instantly.ai campaign endpoint via API key
The n8n HTTP Request node sends a POST to the Instantly leads endpoint, adding the contact to your specified campaign.
↓
4
Response logged: campaign ID, timestamp, recipient
Instantly returns a confirmation response. The campaign ID and a timestamp are captured for the email tracking log.
↓
5
Second Google Sheet records all triggered emails
A separate sheet tab logs every triggered outreach: company name, email address, audit date, campaign ID, and timestamp. This is your sending record.
INSTANTLY API PLAN NOTE

The Instantly.ai API is available on Growth plans and above. The integration uses the campaign/lead endpoints. Different Instantly plan tiers may have different rate limits on API calls. Worth verifying your plan supports the volume you need before going live.

Error Handling

Every failure mode is caught, logged, and skipped. The pipeline never stops mid-run because one URL had an issue.

Error Type What Happens Sheet Status Pipeline Impact
URL timeout (15s) Logged, skipped TIMEOUT Continues
Bot detection block Retry with stealth, then skip BLOCKED Continues
DNS failure Logged DNS_ERROR Continues
Instantly API error Retry once, then log FAIL_EMAIL Continues
Google Sheets rate limit Batch writes with delay N/A Pauses briefly
NOTHING STOPS THE RUN

Every error type is caught and logged. A single failed URL never stops the remaining 499. The email log sheet gives you full visibility into what was sent, what wasn't, and why.
