What you asked for

The application requirement was a detailed answer to one scenario: 2,000 products from multiple suppliers, messy data (inconsistent names, missing specs, duplicate SKUs, mixed image formats, no standard categories), build an internal AI-powered product matching and search tool so the team can find compatible products faster and clean up data faster.

The full scenario answer is on the Solution page. Short version is below.

The approach in one paragraph

Targeted AI for the judgment parts, deterministic code for everything else. Embeddings handle "are these two product titles semantically close" cleanly; brand and category boundaries get hard rules, not vibes. Each match returns a confidence score the team can see, which is what makes the difference between a tool people trust and a tool they abandon after the first wrong match.

What ships when

  • Week 1, runnable core: ingest every supplier CSV, normalize, dedupe with fuzzy SKU + brand + spec hash matching, embed with OpenAI text-embedding-3-small, store in FAISS or sqlite-vec, CLI search with confidence scores
  • Week 2, team UI: thin Next.js or Streamlit interface, search box, results grid, compare view, "this match is wrong" feedback button
  • Week 3+, iteration: watch real queries, tune ranking, add filters, use the feedback table to improve match quality
Paid test first

10 hours fixed at $400, on a slice of real data (200 to 500 products, 2 to 3 suppliers). Output is a working tool, docs, and handoff. You see actual matching quality on actual data before committing to the full MVP. Details on the Onboarding page.

Buy vs build

The job post says "if a cheap SaaS tool or existing API solves the problem better than custom code, we expect you to say so." Agreed. If your supplier feeds are cleaner than I am assuming, a hosted product search like Algolia or a vector DB like Pinecone might cover this at low monthly cost with no engineering work. The paid test is the cheapest way to find out which path fits, because we work on real data instead of guesses.
