TIMELINE

What ships, when

Paid test first, MVP next, iteration after. Each phase has a concrete output you can review before the next phase starts.

Phase shape

Four phases. The first is a fixed-price test so we both validate fit on real data. Phases two and three are the actual MVP build. Phase four is iteration. Nothing is sequential just for the sake of it; every phase ends with a working artifact you can look at.

Phase 0, Paid Test
10 hours fixed at $400

Working tool on a slice of your data

Pick 200 to 500 products and 2 to 3 supplier CSVs. I deliver: normalized data, working dedupe with confidence scores, CLI search returning top-K matches with confidence, a short written report on what the matching quality looks like on your actual data, and the code.

Output: runnable code, written report, matching quality assessment. You decide whether to continue.

Phase 1, Week 1 MVP
~25 to 35 hours

Full 2,000 product pipeline, CLI search

Apply the paid-test pipeline to your full catalog. All suppliers, all products. Set up the data refresh process (manual or scheduled). Embeddings and vector store sized for the real volume. CLI search that two team members can use immediately.

Output: working pipeline on all 2,000 products, repeatable refresh process, CLI in their hands.

Phase 2, Week 2 UI
~20 to 30 hours

Team interface (Next.js or Streamlit)

Whichever framework matches your stack. Search box, results grid with confidence scores, side-by-side compare view, "this match is wrong" feedback button that writes to a corrections table. Authentication if your network requires it.

Output: deployed UI two team members can use without the terminal.

Phase 3+, Iteration
Hourly, as needed

Tune ranking, add filters, close the feedback loop

Watch what the team actually searches for. Adjust embedding inputs, ranking weights, and filters based on real usage. Use the corrections table to improve match quality systematically. Add features the team asks for after seeing the v1.

Output: better matching every week, in proportion to how much the team uses it.

What the timeline does not pretend to be

  • Not a Gantt chart with daily milestones. Software estimates that precise are usually lying.
  • Not a fixed delivery date for the full MVP. Phase 0 (paid test) is fixed. Phase 1 and Phase 2 are scoped in hours, not deadlines, so we can adjust if your data reveals something I didn't account for.
  • Not a "we'll figure it out as we go." Each phase has a defined output and a stopping point.

Calibration after Phase 0

Once the paid test ships, we'll have real numbers: how messy the data actually is, what the matching quality looks like, where the failure modes are. Phase 1 and Phase 2 estimates get tightened at that point. If the data is cleaner than I assumed, the estimates go down. If it is messier, we discuss scope before continuing.
