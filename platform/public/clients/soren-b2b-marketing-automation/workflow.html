Two worked examples showing exactly what happens to a lead at every stage. Real data formats, actual scoring math, and every failure mode handled. For the architecture decisions behind this, see the Solution page.

Pipeline Overview

Five stages. Each one has a defined input, a defined output, and a log entry. If anything breaks, it surfaces immediately.

1
Capture
Make.com webhooks
Each source has its own webhook. LinkedIn replies via HeyReach, Apollo list imports, web form submissions, Reddit keyword matches. Failures on one channel don't affect the others.
2
Normalize + Deduplicate
Make.com data transform + CRM lookup
Map source-specific fields to the canonical schema (see Solution: Data Architecture). Check CRM for existing record by email. Duplicates merge engagement data instead of creating new contacts.
3
Enrich
Apollo API via Make.com
Fill missing fields: company size, industry, seniority, title. Leads that Apollo can't match get flagged as enrichment_status: "partial" and routed to a review queue.
4
Score
n8n code node
Engagement signals + firmographic data produce a 0-100 score. Weights are stored in a Google Sheet so you can adjust them without editing the workflow.
5
Route
n8n conditional branch
Hot (80+): instant Slack alert + CRM priority flag. Warm (50-79): 5-touch nurture sequence. Cool (20-49): weekly digest. Cold (0-19): archive with quarterly re-score.

Worked Example: LinkedIn Lead via HeyReach

A prospect accepts a LinkedIn connection request from one of Soren's outreach campaigns. Here's exactly what happens, with the actual data at each stage.

Stage 1: Capture HeyReach fires a webhook

When the prospect accepts the connection request, HeyReach sends this payload to the Make.com webhook:

{
  "event": "connection_accepted",
  "prospect": {
    "firstName": "Jane",
    "lastName": "Chen",
    "email": "jane.chen@acme.io",
    "companyName": "Acme Corp",
    "title": "VP Marketing",
    "linkedinUrl": "linkedin.com/in/janechen"
  },
  "campaign": {
    "id": "camp_saas_vp_q2",
    "name": "SaaS VP Outreach Q2"
  },
  "timestamp": "2026-04-01T10:23:14Z"
}

Stage 2: Normalize Map to canonical schema

Make.com maps the HeyReach fields to the standard lead format. prospect.firstName becomes first_name. prospect.companyName becomes company. The source channel is set to linkedin_heyreach based on the webhook endpoint.

Before writing to CRM, Make.com checks if jane.chen@acme.io already exists. It doesn't, so the record proceeds to enrichment.

Stage 3: Enrich Apollo fills the gaps

HeyReach gave us a name, title, and company. But we don't have company size, industry, or seniority level. Make.com sends the email to Apollo's /v1/people/match endpoint:

// Apollo API response (relevant fields)
{
  "person": {
    "title": "VP of Marketing",
    "seniority": "vp",
    "organization": {
      "name": "Acme Corp",
      "estimated_num_employees": 340,
      "industry": "Computer Software",
      "short_description": "B2B SaaS platform for..."
    }
  }
}

Now we have everything needed for scoring. The normalized record looks like this:

{
  "email": "jane.chen@acme.io",
  "first_name": "Jane",
  "last_name": "Chen",
  "company": "Acme Corp",
  "title": "VP of Marketing",
  "company_size": 340,
  "industry": "Computer Software",
  "seniority": "vp",
  "source_channel": "linkedin_heyreach",
  "capture_ts": "2026-04-01T10:23:14Z",
  "enrichment_status": "complete",
  "lead_score": null
}

Stage 4: Score Engagement + firmographic math

Make.com fires the enriched record to n8n via webhook. The scoring code node calculates:

Engagement Score
LinkedIn connection accepted+15
Part of active campaign sequence+5
Engagement subtotal= 20
Firmographic Score
VP-level seniority+20
Company size 200-500 (target range)+10
Software industry (target vertical)+15
Firmographic subtotal= 45
Total Lead Score65 / 100

Stage 5: Route Classification: Warm

Score of 65 falls in the Warm band (50-79). n8n triggers:

  • CRM record created with score 65 and pipeline_stage: "nurture"
  • 5-touch email sequence starts. Day 1: personalized intro referencing the LinkedIn connection. Day 3 and Day 7: follow-ups if no reply
  • If Jane replies to any email, the sequence stops and she gets reclassified as Hot automatically
  • Added to the weekly team digest under "New warm leads this week"
Why not Hot?

Jane's engagement score is only 20 because she accepted a connection request but hasn't replied to a message yet. If she replies to the first nurture email, the engagement score jumps by +20 (message reply signal), pushing her total to 85. That crosses the Hot threshold and triggers the instant Slack alert.

Worked Example: Apollo Prospecting Import

A different path through the same pipeline. Soren's team exports a prospecting list from Apollo. These leads come pre-enriched but with zero engagement signals.

Stage 1: Capture Scheduled Apollo pull

Make.com polls Apollo's saved search API on a daily schedule. New contacts since the last run get pulled in batch. Today's batch includes:

{
  "email": "mark.hoffmann@nordtech.de",
  "first_name": "Mark",
  "last_name": "Hoffmann",
  "title": "Marketing Manager",
  "seniority": "manager",
  "organization": {
    "name": "NordTech Solutions",
    "estimated_num_employees": 85,
    "industry": "Information Technology"
  }
}

Stage 2: Normalize Already structured

Apollo data maps cleanly to the canonical schema. The source channel is set to apollo_import. Deduplication check passes. No existing record found.

Stage 3: Enrich Skipped

Apollo contacts arrive pre-enriched. The enrichment step detects that company_size, industry, and seniority are already filled. It sets enrichment_status: "complete" and passes through without making an API call. No wasted Apollo credits.

Stage 4: Score High firmographic, zero engagement

Engagement Score
No interaction yet (prospecting import)+0
Engagement subtotal= 0
Firmographic Score
Manager-level seniority+10
Company size 50-200+10
IT industry (adjacent vertical)+10
Firmographic subtotal= 30
Total Lead Score30 / 100

Stage 5: Route Classification: Cool

Score of 30 falls in the Cool band (20-49). n8n triggers:

  • CRM record created with score 30 and pipeline_stage: "drip"
  • Added to the weekly digest under "New cool leads"
  • Enters long-term drip: one email every 2 weeks with relevant content
  • If Mark opens and clicks a drip email, engagement score updates (+15 for open+click), potentially moving him to Warm
Apollo imports start Cool by design

Prospecting imports have zero engagement signal. They haven't interacted with anything yet. The pipeline puts them in a low-touch drip until they show interest, then escalates automatically. This keeps your team focused on leads that are already engaging rather than chasing cold lists.

Scoring Model

The score combines two dimensions. Each runs 0-50. The total is 0-100. All weights are stored in a Google Sheet that you can edit without touching the n8n workflow.

Engagement signals

Signal Points Source
Web form submission +25 Direct intent signal
Email reply +20 IMAP polling via n8n
LinkedIn message reply +20 HeyReach webhook
Email open + link click +15 Email tracking pixel + link redirect
LinkedIn connection accept +15 HeyReach webhook
Part of active campaign +5 HeyReach campaign metadata

Engagement signals stack. A lead that accepts a connection (+15), is in a campaign (+5), and replies to a message (+20) scores 40/50 on engagement alone.

Firmographic signals

Signal Points Source
C-level title (CEO, CMO, CRO) +25 Apollo enrichment
VP-level title +20 Apollo enrichment
Director-level title +15 Apollo enrichment
Manager-level title +10 Apollo enrichment
Target industry match +15 Apollo enrichment
Adjacent industry +10 Apollo enrichment
Company size 200-500 (sweet spot) +10 Apollo enrichment
Company size 50-200 or 500+ +5 Apollo enrichment

Routing thresholds

Score Band What Happens
80-100 Hot Instant Slack alert with contact details and CRM link. Priority flag in CRM. Calendar booking link attached for immediate outreach.
50-79 Warm 5-touch nurture sequence (Day 1, 3, 7, 14, 21). Auto-stops on reply. Reclassifies to Hot if engagement score crosses threshold.
20-49 Cool Weekly digest email to your team. Bi-weekly content drip to the lead. Re-scores on any new engagement.
0-19 Cold Archived in CRM. Quarterly batch re-score checks if ICP definition changed. No active outreach.
Thresholds are yours to tune

80, 50, and 20 are starting points calibrated for a typical B2B pipeline. After 2-3 weeks of data, you'll see where your natural breakpoints are. Changing them is one edit in the Google Sheet. The n8n workflow reads the sheet at the start of every scoring run.

Error Handling

Every external system in this pipeline can fail. Here's what happens when each one does.

Scenario Detection Response
Apollo API rate limit (429) HTTP status code check in Make.com Queue remaining leads with exponential backoff. Process the batch over minutes instead of seconds. Already-processed leads aren't affected.
Apollo enrichment fails (person not found) Empty person object or 404 response Set enrichment_status: "partial". Lead proceeds to scoring with available data. Daily digest lists partial records for manual review.
HeyReach webhook payload malformed JSON parse error in Make.com Log the raw payload to a Google Sheets "errors" tab. Send Slack notification with the webhook timestamp so you can investigate. No data loss.
CRM duplicate detected Email match on existing CRM contact Don't create a new record. Instead, update the existing contact's engagement data and recalculate the score. This prevents duplicates and keeps scoring accurate.
n8n scoring node exception Code node throws an error Lead gets routed to manual review queue with the error message attached. Slack alert to you. The error doesn't block other leads in the same batch.
Make.com scenario timeout (40s limit) Execution exceeds time limit Scenario splits into sub-scenarios for large batches. Each sub-scenario handles a chunk of leads independently. If one chunk times out, the rest still process.
Nothing fails silently

Every error condition logs to a Google Sheet and fires a Slack notification. If you wake up to 3 error notifications, you know exactly what happened and where. If you wake up to zero, everything processed normally. The pipeline never stops running because one lead has bad data.
