The Automation Layer

How Make.com and n8n handle the infrastructure behind Soren's B2B marketing pipeline.

Platform Architecture

Two platforms, each doing what it's best at. Make.com is the integration layer: it handles HTTP connections between your tools, API calls to Apollo and HeyReach, CRM sync, and webhook listeners for inbound leads. It's reliable, visual, and easy to audit when something isn't flowing the way you expect.

n8n is the logic layer: it handles anything that needs custom code, conditional branching based on lead attributes, scoring calculations, or retry logic for unreliable third-party APIs. Where Make.com connects A to B reliably, n8n decides what B should actually do when the data arrives.

The two platforms pass data to each other via webhooks. Make.com captures and normalizes incoming leads, then fires a webhook to n8n for scoring and routing. n8n sends results back to Make.com to update the CRM and trigger the right sequence.

Not theoretical

I've built 50+ Make.com scenarios across client projects. These are production pipelines processing real data, not demo environments. The patterns I use here come directly from what's working in production.

Lead Capture

Leads arrive from multiple places: LinkedIn connection replies, Reddit engagement, web form submissions, Apollo prospecting lists, and inbound ad clicks. Each source has a different data format. The capture layer normalizes everything into one schema before anything else happens.

Per-source webhook endpoints

Each source gets its own Make.com webhook. LinkedIn reply triggers from HeyReach come in on one endpoint. Form submissions come in on another. Apollo list exports are pulled on a schedule. This separation makes it easy to debug when one source stops working without touching the others.

Data normalization

LinkedIn gives you a first name, last name, and company. Apollo gives you an enriched record with firmographic data. Web forms give you whatever the prospect typed. The normalization step maps all of these to a consistent schema: first name, last name, company name, title, company size, industry, source channel, and capture timestamp.

Deduplication

Before a lead gets written to your CRM, Make.com checks whether that email or LinkedIn profile URL already exists. Duplicates get flagged and routed to a review queue rather than creating double records or re-triggering sequences for existing contacts.

Enrichment via Apollo

If a lead arrives without full firmographic data (common with LinkedIn and form submissions), Make.com calls the Apollo API to fill in the gaps: company size, industry, decision-maker role, technology stack. Enriched leads score higher and route into more targeted sequences.

Outbound Automation

The outbound layer runs in n8n. It handles the sequences that run after a lead is captured and scored: cold email, LinkedIn follow-up, and response management.

Cold email sequences

n8n manages the send schedule for outbound email campaigns. Day 1 sends the initial message. Days 3 and 7 send follow-ups if there's no reply. n8n monitors the email thread for replies using IMAP polling, and when a reply arrives, it cancels any remaining follow-ups automatically. No manual intervention needed to stop sequences for active conversations.

LinkedIn outreach via HeyReach

HeyReach handles the LinkedIn connection requests and messages. n8n triggers the outreach campaign via the HeyReach API when a lead meets the threshold for LinkedIn contact (based on scoring). Reply data from HeyReach flows back into n8n via webhook, updating the lead record and routing hot responses to your team immediately.

Follow-up cadence

Timing is configurable per campaign. You set the day offsets, the channel order (email first vs LinkedIn first), and the stopping conditions. These settings live in a Google Sheet, so you can adjust cadence for a new campaign without editing the workflow.

Lead Scoring

Scoring runs in n8n as a custom code node. It takes the normalized lead record and produces a numeric score. That score determines which sequence the lead enters and how urgently your team gets notified.

Engagement scoring

Points are added for each engagement signal: email opened, link clicked, replied, visited the proposal site, replied to a LinkedIn message. Higher engagement means a warmer lead, even if the firmographic fit is average.

Firmographic scoring

Company size, industry match, and decision-maker seniority each contribute points. A VP of Marketing at a 200-person SaaS company scores higher than a coordinator at a 10-person agency, even with identical engagement.

Routing thresholds

Three tiers, each with a different action:

  • Hot (75+): Immediate Slack alert to your team, moved to priority pipeline stage in CRM
  • Warm (40-74): Enters active nurture sequence, weekly summary to your team
  • Cold (below 40): Enters long-term drip, no active outreach until score changes

Thresholds are yours to adjust. The scoring model gets documented so you can reason about why a lead is where it is.

Here's how each tool in Soren's stack connects to the pipeline:

Tool Integration Method What It Does
Apollo REST API via Make.com Lead enrichment, prospecting list ingestion
HeyReach Webhook + API via n8n LinkedIn outreach triggers, response capture and routing
LinkedIn Ads Sheets export + Make.com Campaign data ingestion for lead source attribution
Google Ads API via Make.com Campaign performance data for scoring context
Ahrefs / SEMrush CSV export + Make.com Organic lead source tracking, keyword-to-conversion data
CRM (your choice) Native Make.com module Lead storage, pipeline stage management, sequence tracking
Email (SMTP/Gmail) n8n email node Outbound sequences, reply detection, team notifications
Google Sheets Native Make.com module Rule configuration, scoring thresholds, activity log
The point isn't replacing your tools

Every tool in that table stays. What changes is that they talk to each other automatically. A lead that enters via LinkedIn Ads gets enriched by Apollo, scored in n8n, and routed to HeyReach for follow-up, all without anyone touching a keyboard.
