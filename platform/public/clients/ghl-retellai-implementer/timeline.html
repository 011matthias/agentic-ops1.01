Phase 1: Test Setup

Week 1

The first week is about getting me up to speed on your stack and proving I can execute a full client setup without hand-holding. No ongoing commitment until you're satisfied with the output.

1
Receive access and SOPs

You share Loom walkthroughs, written SOPs, and access to GoHighLevel, n8n, and Retell AI. I work through these before touching anything live. If anything is ambiguous, I'll flag it with a specific question rather than guessing.

2
Study the master snapshot structure

I review the master GHL snapshot: pipeline stages, custom fields, sequence triggers, and funnel structure. I also review your existing n8n workflows to understand the patterns before I start cloning. This is where questions surface early rather than mid-setup.

3
Set up one client environment end-to-end

Snapshot clone, post-snapshot reconfiguration (webhook URLs, credentials, field mappings), Retell AI agent configuration (system prompt, dynamic variables, voice selection), n8n workflow instances (webhook triggers, API calls, error handling). The full sequence on one real or sandbox client.

4
Test the full call flow

Create a test lead in GoHighLevel, move it through the relevant pipeline stage, and verify every step: webhook fires to n8n, Retell call executes, callback arrives, GHL contact record updates with the correct outcome, Airtable row syncs, Twilio SMS sends. Pass or document exactly which step failed and why.

5
Document blockers and process notes

Everything that took longer than expected, any SOP step that was ambiguous, any pattern I'd want to template for future setups. This documentation becomes useful input whether or not we continue past Week 1.

Evaluation gate

This is where you evaluate my output directly: did I follow the SOPs correctly, does the end-to-end call flow work, is the documentation clear, was communication prompt and specific. No ongoing commitment until you're satisfied. If it doesn't meet your bar, you have a fully documented client environment as a usable artifact, not just a sunk cost.

Phase 2: First Live Clients

Weeks 2-3

After the test setup clears your bar, we move to live client environments. This phase is about establishing the working rhythm before volume picks up.

1
Transition from test to live

The first live setups may surface differences between the sandbox and real client accounts. GoHighLevel sub-account configs vary: different custom fields, different pipeline stage names, different sequence structures. I document these variations as they appear so the process gets tighter with each setup.

2
Establish the change request workflow

We agree on how requests come in (async message, shared doc, ticketing tool), how I confirm scope before starting, and how I close and communicate completion. Getting this right early prevents ambiguity when you have 5+ active clients generating 2-3 requests per week each.

3
Handle first change requests

Retell prompt refinements, n8n workflow updates, GHL pipeline adjustments. I work through these in the background and report back with what changed, why, and what to watch for. Each change is documented so your team has a changelog per client.

4
Refine n8n workflow templates

After two or three setups, patterns emerge. Steps that always need adjustment, variables that differ per client, error-prone configuration points. I propose template improvements that reduce setup time going forward. The goal is to bring the 3-4 hour reconfiguration down with each iteration.
