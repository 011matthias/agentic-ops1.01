Pipeline Flow


    
The complete GHL-to-Retell pipeline has two parallel flows. The first handles outbound call creation when a contact reaches the right pipeline stage. The second handles the callback from Retell after the call completes, writing the outcome back to GHL.


    

        
Flow 1: GHL → Retell AI (Outbound Call)

        
When a GHL pipeline stage changes to "qualified," the webhook fires. The IF node validates the stage, and if it passes, the workflow builds the Retell API payload with dynamic variables (contact name, services, available slots) and initiates the phone call.

        

            Webhook Trigger
            →
            Stage Filter
            →
            Retell API Call
        

    


    

        
Flow 2: Retell → GHL (Call Outcome)

        
Retell sends three webhook events per call: call_started, call_ended, and call_analyzed. The workflow filters for call_analyzed (which contains the transcript and summary), then updates the GHL contact with the call outcome via the GHL API.

        

            Callback Webhook
            →
            Event Filter
            →
            GHL Contact Update
            →
            Audit Log
        

    


    

        
Per-Client Configuration

        
When onboarding a new client, three things change: the GHL webhook URL (per sub-account), the Retell agent ID (per client voice/prompt), and the dynamic variables (services, time slots). Everything else stays the same. The template is designed to clone and configure in under 30 minutes per client.

    


    
    
Node Walkthrough


    

        
        Flow 1: Outbound Call
    


    

        

            

                
1

                

            

            

                
GHL Pipeline Webhook

                
Webhook (POST)

                
Listens for GHL pipeline stage change events. When a contact moves to a new stage in any GHL sub-account, this webhook fires with the contact data, phone number, and current pipeline stage.

            

        


        

            

                
2

                

            

            

                
Check Pipeline Stage

                
IF Node

                
Filters for the "qualified" stage. Only contacts who reach this specific stage trigger an outbound call. All other stage changes are routed to a skip node, preventing unnecessary API calls and protecting the client's phone budget.

            

        


        

            

                
3

                

            

            

                
Create Retell AI Call

                
HTTP Request (POST)

                
Calls the Retell AI API (v2/create-phone-call) with the contact's phone number, client-specific agent ID, and dynamic variables. The dynamic variables (client name, services, available time slots) are injected into the AI agent's conversation in real time.

            

        


        

            

                
!

            

            

                
Skip (Wrong Stage)

                
Set Node (False Path)

                
Handles contacts that are not in the "qualified" stage. Logs the skip reason for debugging. No API call is made, no phone budget is spent.

            

        

    


    


    

        
        Flow 2: Call Outcome
    


    

        

            

                
5

                

            

            

                
Retell Callback Webhook

                
Webhook (POST)

                
Receives Retell AI call events. Each call generates three events: call_started, call_ended, and call_analyzed. The analyzed event contains the full transcript and AI-generated call summary.

            

        


        

            

                
6

                

            

            

                
Filter call_analyzed Only

                
IF Node

                
Only processes call_analyzed events. The started and ended events are dropped (no GHL update needed for those). This prevents duplicate writes and ensures the transcript is available before updating the contact record.

            

        


        

            

                
7

                

            

            

                
Update GHL Contact

                
HTTP Request (PUT)

                
Writes the call outcome back to GHL via the Contacts API. Updates two custom fields: call_outcome (the AI-generated summary) and call_transcript (the full conversation). The GHL contact ID is pulled from the Retell call metadata.

            

        


        

            

                
8

            

            

                
Log Outcome

                
Set Node

                
Creates an audit log entry with the call ID and contact ID. Useful for debugging and tracking call processing rates across clients.
