Project Brief

Jamiane's Project, Mapped Out

Your situation on Field Nation, why the tools you picked are the right ones, and what constraints the build has to work within.

The Situation

You're a Field Nation provider who processes incoming work order notifications manually. When a new job arrives by email, you review it -- checking pay rate, location, work type, and your calendar -- and then navigate to Field Nation to accept or request it.

The core problem is timing. Field Nation is first-come-first-served, and the time it takes to read an email, evaluate a job, and click through to the platform is where opportunities get lost to faster competitors. The manual loop isn't just slow -- it means you have to be available and attentive around the clock to stay competitive.

You've already identified the right tools: n8n for orchestration, Playwright for browser automation, and optionally the Claude API for intelligent email parsing. The system runs on your VPS, which keeps recurring costs low and keeps your credentials off third-party platforms.

Field Nation Ecosystem

Field Nation is the leading IT field service marketplace, connecting enterprises with independent technicians for on-site work. The platform processes over a million work orders per year across installation, repair, and survey job types.

Field Nation does publish a developer API at developer.fieldnation.com with 200+ REST endpoints and webhook support. After reviewing that documentation, it's clear the API is designed for the buyer side of the marketplace -- companies that post work orders, manage assignments, and track completion at scale. Provider-side actions (accepting a job, requesting a job, submitting a counter-offer) happen through the web interface, not the API.

That's not a gap or an oversight in the API design -- it reflects how the two sides of the marketplace operate. Buyers need programmatic access to manage thousands of assignments. Providers act on individual opportunities through the UI.

Why Playwright and not the API

We reviewed Field Nation's API documentation before proposing this approach. Browser automation isn't a workaround -- it's the correct tool for provider-side workflows. The API simply doesn't expose the endpoints you'd need.

Your Requirements

Here's how each requirement from the job posting maps to a specific part of the delivery.

Requirement How it's addressed
Process incoming work order emails n8n IMAP Trigger polls your inbox every 30-60 seconds. Filters by Field Nation sender domain and subject patterns so only relevant emails enter the pipeline.
Apply business rules Decision engine reads your thresholds from a Google Sheet at runtime. Change a value in the sheet and it takes effect on the next email -- no code edits needed.
Accept or request jobs automatically Playwright handles the browser interaction: login, navigate to work order, execute the decision. Session cookies persist between runs.
Run on your VPS Self-hosted n8n and Playwright. No external SaaS dependencies for the core automation. PM2 keeps both processes running and restarts them if they exit.
Low-cost tools n8n self-hosted is free. Playwright is free. Claude API costs roughly $0.002 per email -- about $0.06 per month at 30 emails/day.
Optional Claude API for email parsing Included as the primary parser with a regex fallback option. Claude handles format changes gracefully; regex is faster but brittle if Field Nation updates their template.
Reliable and maintainable Error handling at every stage, session recovery on auth expiry, race condition detection, screenshot audit trail, and a Google Sheets log. Workflow is documented so you can hand it to someone else if needed.

Technical Constraints

These are the prerequisites for the system to run on your VPS. Most standard Linux VPS setups already meet them.

  • ✓
    Node.js 18 or higher
    Required by Playwright. Most distributions ship Node.js 18+ or it's a one-command install via nvm.
  • ✓
    At least 2 GB RAM
    Playwright runs a headless Chromium instance. 2 GB is the practical minimum; 4 GB gives comfortable headroom if other services share the VPS.
  • ✓
    10 GB available disk
    Covers Playwright's Chromium binary, n8n data, and screenshot storage. Screenshots are dated and can be pruned on a schedule if disk is tight.
  • ✓
    n8n self-hosted with IMAP trigger capability
    Standard n8n installation supports IMAP. Works with Gmail, Outlook, and any provider that supports IMAP access.
  • ✓
    Anthropic API key (optional)
    Only needed if you choose Claude API as the email parser. Requires an Anthropic account. The regex fallback has no API dependency.
  • ✓
    Field Nation credentials
    Stored in n8n's encrypted credentials store. Never written to plain text files or exposed in logs.
No desktop environment needed

Playwright runs fully headless -- there's no need for a GUI or display server on the VPS. A standard Ubuntu or Debian server install is sufficient.
