How the Pipeline Works

Five stages from inbox to Field Nation action. Here's exactly what gets built and why each piece is designed the way it is.

Pipeline Overview

Each stage hands off to the next. Email arrives, gets parsed, hits your rules, triggers a browser action, and gets logged. If any stage fails, the error surfaces immediately -- nothing silently disappears.

1
Email Ingestion
n8n IMAP Trigger

n8n polls your inbox on a short interval (30-60 seconds is typical). It filters by Field Nation's sender domain and subject line patterns so only relevant work order notifications enter the pipeline. Non-matching emails are ignored entirely.

2
Email Parsing
Claude API or regex

The email body is passed to either Claude API or a regex parser depending on your preference. The output is a structured JSON object with every field you need to make a decision: job title, location, pay rate, work type, date, and whether a counter-offer is allowed.

3
Decision Engine
Your rules, evaluated at runtime

The parsed fields are evaluated against your business rules. Rules are stored in a Google Sheet, so you can update thresholds without touching the workflow. The engine outputs one of three decisions: accept, request (with optional counter-offer), or skip.

4
Browser Automation
Playwright on your VPS

Playwright opens a headless Chromium browser on your VPS, logs into Field Nation using your stored credentials, navigates to the work order, and executes the decision. Session cookies are persisted between runs so it doesn't log in from scratch every time.

5
Logging
Google Sheets + notifications

Every run appends a row to a Google Sheet log: timestamp, job title, pay rate, location, decision, action taken, and any notes. A daily summary email gives you an at-a-glance count of accepts, requests, skips, and missed jobs.

Email Parsing

There are two parser options. The right choice depends on how stable Field Nation's email format has been for you.

Option A: Claude API

The Claude API reads the full email body and extracts the fields you need based on meaning, not fixed patterns. When Field Nation changes their email template (which they do periodically), the parser keeps working without any code changes on your end. The per-email cost is approximately $0.002 -- negligible at any volume.

Option B: Regex

A regex parser matches known patterns in the email text. It's faster (no API call) and has zero per-email cost. The tradeoff: if Field Nation updates their email layout, the patterns break and need updating.

My recommendation

Start with Claude API. The resilience is worth the fraction of a cent per email, and you won't need to maintain regex patterns when Field Nation pushes a template update.

Either way, the parser outputs the same structured format:

Job Title: Network Switch Installation
Location: Miami, FL (23 miles)
Pay Rate: $45/hr + travel
Work Type: Installation
Date: Mar 30, 2026 9:00 AM
Counter-offer: Allowed

Decision Engine

Your rules live in a Google Sheet. The n8n workflow reads them at the start of each run, so any change you make takes effect on the next email -- no workflow edits, no deployments.

Pay rate >= $40/hr Accept
Pay rate $25 -- $39/hr Request with counter-offer
Pay rate < $25/hr Skip -- log and move on

Browser Automation

Playwright runs headless Chromium on your VPS, managed by PM2 so it restarts automatically if the process ever exits unexpectedly.

Session management

After the first login, Playwright stores your session cookies to disk. Subsequent runs load the saved session and skip the login step entirely. When a session eventually expires, the script detects the Field Nation login page, re-authenticates with your stored credentials, and continues -- no manual intervention needed under normal circumstances.

Race conditions

Field Nation is first-come-first-served, so by the time the browser reaches a work order, it might already be taken. The script checks the work order status before attempting any action. If it's already accepted by someone else, it logs "MISSED -- already accepted" and exits cleanly. No errors, no crashes.

Screenshot audit trail

Every accept, request, and skip action captures a screenshot. These are stored on your VPS in a dated folder so you have a visual record of every action the automation took.

If Field Nation presents MFA or CAPTCHA

The script detects unexpected screens (login challenges, CAPTCHA prompts) and sends you a notification with a screenshot. You complete the challenge manually in a browser, and the automation picks up from a fresh session on the next email. This is a rare edge case -- most Field Nation sessions stay valid for days.

Monitoring

You'll have two places to check what the automation has been doing: a running Google Sheets log and a daily summary email.

Google Sheets log

Each run appends one row with these columns: Timestamp, Job Title, Pay Rate, Location, Decision, Action Taken, and Notes (used for "already accepted", error messages, and manual review flags). You can filter, sort, and build your own analysis on top of it.

Daily summary

Every morning you'll get an email (or Slack message, your choice) with the previous day's counts: how many jobs were accepted, requested, skipped, missed to race conditions, and flagged for manual review. No need to dig into the log unless something looks off.

Error alerting

If the Playwright process crashes, the IMAP poller fails, or the Claude API returns an error, you get a notification immediately. The failure doesn't sit quietly until you notice jobs have stopped being processed.
