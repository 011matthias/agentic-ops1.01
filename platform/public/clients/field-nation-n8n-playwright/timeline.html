Delivery Schedule

The project runs over 3 focused days. Each day ends with a working deliverable you can test -- not just progress reports.

1
Email Pipeline + Decision Engine
n8n email trigger, Claude API parsing, business rule routing
  • Set up n8n IMAP trigger scoped to Field Nation sender address
  • Configure Claude API integration with structured extraction prompt
  • Build decision engine with your business rules -- minimum pay rate, max distance, work type filters
  • Test against 2-3 sample emails you provide (real ones give the most accurate result)
  • Connect Google Sheets logging for every decision
✓ Working email-to-decision pipeline -- parse any Field Nation email and route it correctly
2
Playwright Browser Automation
Login flow, accept/request actions, edge case handling
  • Build Field Nation login flow with session cookie persistence (avoids re-login on every run)
  • Implement accept, counter-offer request, and skip actions
  • Handle edge cases: expired sessions, already-taken jobs, MFA challenge detection
  • Save a screenshot after each browser action as an audit receipt
  • Connect Playwright output back to Google Sheets log (action taken, outcome, screenshot path)
✓ End-to-end automation -- email in, browser action out, full audit trail
3
VPS Deployment + Live Testing
Production install, PM2 process management, handover
  • Deploy n8n workflow to your VPS via SSH
  • Install Playwright and headless Chromium in the server environment
  • Set up PM2 to keep everything running and auto-restart on crash
  • Run a live test with real Field Nation work orders to confirm end-to-end behavior
  • Write the system documentation -- how to update business rules, restart the automation, and read logs
✓ Production-ready system running on your VPS with documentation and handover

What You Need First

I can start on Day 1 as soon as these are in hand. Most of it takes under 10 minutes to put together on your side.

  • 🔒
    Field Nation login credentials
    Username and password for your Field Nation technician account. These stay on your VPS -- they're not stored anywhere else.
  • 🖥
    VPS access
    SSH credentials or remote desktop access. Ubuntu/Debian preferred -- most VPS providers default to this.
  • 📧
    2-3 sample work order emails
    Forward a few real Field Nation notification emails. These let me calibrate the Claude API extraction prompt to your actual email format before Day 1 testing.
  • 📈
    Your business rules
    Minimum pay rate you'll accept, maximum travel distance, any work types to always skip or always accept. A quick message or voice note is fine -- I'll translate it into decision engine logic.
  • 💌
    Email provider details
    Which email service receives your Field Nation notifications (Gmail, Outlook, etc.) and whether you have IMAP access enabled. Gmail users may need to create an app password.
  • 🤖
    Claude API key (optional)
    If you have one, great. If not, I'll use mine during development and hand over the configuration so you can swap in your own key at delivery.

Fill out the onboarding form and I can start the same day. The sample emails are the most useful thing -- they let me test the parsing logic against your real data before writing a line of browser automation code.

After Delivery

Day 3 isn't the end -- it's when the system starts earning its keep. Here's what comes with the handover and what's available after.

📘
System documentation
A written guide covering how to update business rules in the Google Sheet, how to restart the automation if it stops, how to read the decision log, and what each error state means.
🛠
1 week of bug fixes
If something breaks during normal operation in the 7 days after delivery, I'll fix it at no extra charge. This covers Field Nation UI changes, unexpected email formats, and anything that slips through testing.
📈
Business rule updates
The decision engine is built so you can change pay thresholds, distance limits, and work type filters by editing a Google Sheet -- no code changes needed. Bigger rule changes (new logic branches) are available as follow-on work.
🌎
Additional marketplace support
The same pattern applies to other job platforms -- Workmarket, Dice, etc. If you work across multiple marketplaces, the architecture is already designed to add new sources without rewriting the core.
📊
Reporting dashboard
Weekly or monthly stats on jobs accepted, missed, revenue impact, average pay rate -- built on top of the existing Google Sheets log. Available as an optional add-on after delivery.
📱
Mobile notifications
Push alerts when a job hits the manual review queue (MFA triggered, parse failure, unusually high-value job). Available via Telegram, Slack, or SMS depending on your preference.
