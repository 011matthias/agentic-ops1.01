Solution

How It Works

Two n8n workflows working together -- one that answers lead questions in real time, one that lets you swap property listings between meetings without any configuration.

Lead Response Workflow

This is the workflow your audience sees during the demo. A lead question lands in Google Sheets, the AI reads the property listing, and an SMS hits the phone before anyone finishes reading the question out loud.

Lead Response -- step by step
1
Trigger
Google Sheets -- New Row
The workflow watches your demo Sheet for new rows. Each row contains three columns: lead_name (the prospect's name), phone (their mobile number in E.164 format, e.g. +15551234567), and question (the property question typed by the agent).
2
AI
AI Agent -- Vector Store Lookup
The AI Agent node receives the question and queries the Simple Vector Store, which holds the chunked text of the current property PDF. The agent retrieves the most relevant passages and composes a response grounded entirely in that document.
3
Compose
Prompt -- White-Glove Tone, SMS Length
The system prompt instructs the AI to respond as a professional, Houston-based real estate assistant. Responses are kept under 160 characters so they arrive as a single SMS segment. The agent addresses the lead by first name using the lead_name field from the row.
4
Send
Twilio -- Send SMS
The composed response is sent via the Twilio node to the phone number in the row. The Twilio node uses your account SID, auth token, and a dedicated Twilio phone number. No coding required -- all configured in the node's credential fields.
5
Log
Google Sheets -- Write Response and Status
After the SMS is sent, the workflow writes the AI's response text back into the same row and marks a status column as "sent". If anything fails, the status turns "error" and an error_message column captures the reason. The Sheet becomes a live log of every interaction.
The Demo Moment

From row added to SMS received takes under 10 seconds. The agent watches the Sheet row update in real time while the lead's phone buzzes. This is the moment that closes the room.

PDF Ingestion Workflow

This is the behind-the-scenes workflow that makes the demo reusable. Drop a new property listing PDF into a designated Google Drive folder and the knowledge base updates automatically -- no editing nodes, no redeploying, no configuration changes.

Property swap -- step by step
1
Trigger
Google Drive -- Folder Watch
The workflow polls a designated Google Drive folder (e.g., "Property PDFs") for new files. When a PDF is detected, the workflow starts automatically. Only PDF files are processed -- other file types are ignored.
2
Extract
PDF Text Extraction
The PDF binary is passed through n8n's PDF extraction node, which pulls out all readable text content. Property listing flyers typically yield 400-1200 words of clean text covering bedrooms, bathrooms, square footage, price, features, and neighbourhood details.
3
Chunk
Text Chunking
The extracted text is split into overlapping chunks (default: 500 tokens with 50-token overlap). Chunking ensures the vector retrieval returns the most relevant section for each question rather than the entire document at once.
4
Load
Vector Store Rebuild
The existing vector store is cleared and rebuilt with the new chunks. This replaces the previous property's data entirely -- the AI Agent will now answer questions about the new listing only. The rebuild typically completes in 2-5 seconds for a standard one-page listing flyer.
5
Confirm
Status Update in Control Sheet
A dedicated "Control" tab in your Google Sheet is updated with the filename of the loaded property, the timestamp of the load, and a status indicator ("ready"). Before the next meeting you can glance at this tab to confirm the right listing is loaded.
Between-Meeting Reset

To prep for the next meeting: drop the new PDF into the Drive folder, wait 5 seconds for the status tab to show "ready", then clear the question rows from the demo Sheet. That is the entire reset procedure.

Error Handling

Live demos break at the worst moments. Every failure path is accounted for so you can recover cleanly in front of a prospect without losing your composure.

Failure Scenario What Happens Visible Signal
SMS delivery fails (Twilio error) Twilio node error is caught by the workflow's error branch. The status column in the Sheet row is set to "error" and the error_message column captures the Twilio error code. Row turns red in the Sheet
PDF parse fails (corrupted or scanned image) The extraction node error is caught. The Control Sheet status is set to "parse_error" with the filename. The existing vector store is left untouched so the previous property still works. Control Sheet shows "parse_error"
Empty vector store (no PDF loaded yet) The AI Agent detects no relevant chunks were retrieved and responds with a graceful fallback message ("I don't have the listing details loaded yet -- the agent will follow up.") rather than crashing. SMS delivers a safe fallback message
OpenAI rate limit n8n's built-in retry logic retries the AI Agent node up to 3 times with exponential backoff. If all retries fail, the row is marked "error" and the error message notes the rate limit. Row turns red after ~30 seconds
Twilio rate limit Twilio allows 1 outbound SMS per second on a standard number. A short wait node is added between batch sends to stay within limits. For the demo (single row at a time), this is never triggered. No visible delay in single-send demos
Invalid phone number Twilio rejects numbers that are not in valid E.164 format. The error is caught and logged to the Sheet row. A validation note in the Loom walkthrough covers how to format numbers correctly. Row error message: "Invalid phone number"
Demo Safety

Every row that fails shows a red status in the Sheet immediately. You will never sit in silence wondering if something broke -- the workflow tells you exactly what happened and where.
