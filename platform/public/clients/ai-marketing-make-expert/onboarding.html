On credential sharing

We'll agree on a secure transfer method before contract. Options include a shared password manager entry, an encrypted message, or scoped API keys with read-only access where the platform supports it. We don't store credentials outside Make.com's connection manager.

Week 1 Plan

The goal for Week 1 is a working end-to-end path for a single test client through the first data ingestion scenario. Nothing in production, but real API calls against real credentials.

Days 1-2

Read the system design document end-to-end. Map scenario dependencies against your build plan. Set up the Make.com workspace with folder structure and naming conventions. Document any questions from the spec before touching any modules.

Days 3-4

Configure the Google Sheets KB with a test client row. Build the first data ingestion scenario against that test client. Connect Google Ads or Meta (whichever is simpler to test with) and confirm real data is coming through before connecting Claude.

Day 5

Run the first scenario end-to-end with the test client. Document environment variables, webhook URLs, and connection inventory for that scenario. First weekly check-in call - review what's working, surface any spec questions, confirm the Week 2 target.

Why we read before we build

Days 1-2 aren't billable prep time - they're part of the engagement. A spec as detailed as yours has dependencies that aren't obvious until you've read it fully. Building before understanding the full picture means rework later. We don't skip this step.

Communication

Everything async-first, with one synchronous checkpoint per week. You shouldn't need to monitor Make.com to know what's been delivered.

Weekly check-in calls
Your preferred day and time. We review what shipped, run through the test results, and confirm the next scenario target.
Scenario delivery notifications
When a scenario passes its test gate, you get a written summary: what it does, how to test it, and the blueprint export location.
Async updates via Slack or Upwork
Day-to-day questions and blockers handled async. Responses within a few hours on weekdays during US business hours.
Blueprint exports at every milestone
At each phase boundary, a full export of all scenarios built to date. Stored somewhere you control, not just in Make.com.
