Modul-für-Modul erklärt

M1: Mailgun-Webhook (Trigger)

Was passiert: Eine E-Mail kommt bei info@waerme-wimmer.de an. Outlook hat eine Weiterleitungsregel, die eine Kopie an ingest@mg.waerme-wimmer.de schickt. Mailgun empfängt die Mail und schickt sofort einen POST-Request an dieses Make-Modul.

Was reinkommt: Absender, Betreff, Body (HTML + Text), Anhänge als URLs, Zeitstempel.

Vergleich zum IST: Im alten Szenario pollt Make alle 15 Minuten Outlook. Hier kommt die Mail sofort, ohne Verzögerung.

M2: Regex Parser

Was passiert: Der Betreff + Body-Preview wird nach einer HERO-Projektnummer durchsucht.

Beispiel: Betreff = "Re: Angebot HUK-100040 Heizungstausch" → Regex findet HUK-100040 → Projektnummer = 100040

Was wenn nichts gefunden wird: Weiter an Route 1 (KI-Fallback).

M3: Router (2 Routen)

Route 0: Regex hat etwas gefunden → Projekt in HERO nachschlagen Route 1: Regex hat nichts gefunden → KI soll raten

M4: HERO GetProject (Route 0)

Was passiert: Fragt HERO via GraphQL: "Gibt es ein Projekt mit der Nummer 100040?" Wenn ja, liefert Projektdetails (Status, Kontakt, Adresse).

M5: OpenAI Summary

Was passiert: GPT-4o-mini liest den E-Mail-Text, entfernt Signaturen und Disclaimer, fasst den Inhalt in 2-3 Sätzen zusammen. Ergebnis wird als Logbuch-Text verwendet.

Kosten: ca. $0.0003 pro E-Mail. Bei 1.100 Mails/Monat = ca. $0.35/Monat.

M6: HERO Logbuch-Eintrag

Was passiert: Schreibt einen neuen Eintrag ins Projekt-Logbuch in HERO: - Absender (Name + Adresse) - Datum der Mail - OpenAI-Zusammenfassung - Link zur archivierten Mail auf S3

Sichtbar für: Niederlassungsleiter, Mitarbeiter, Buchhaltung, Vertrieb.

M7: Router (3 Routen)

Entscheidet was als Nächstes passiert, basierend auf dem Kontext:

Route 0 (Attachments vorhanden): Hat die E-Mail Anhänge? → M8-M9 Route 1 (Reklamation): Ist der Projektstatus "Reklamation"? → M10-M11 Route 2 (Normal): Weder Anhänge noch Reklamation → fertig, nichts weiter zu tun

M8: S3 Presigned URL generieren (Route 0)

Was passiert: Mailgun hat die Anhänge schon auf S3 gespeichert. Dieses Modul generiert einen temporären Download-Link (Presigned URL), damit HERO die Datei von S3 runterladen kann.

M9: Router Bild vs. Dokument

Bild (PNG, JPG, JPEG): → HERO UploadImage (Kategorie "Bilder vom Kunden") Dokument (PDF, DOCX, etc.): → HERO UploadDocument (Ordner "Allgemein", Typ 688384)

M10: HERO CreateTask (Route 1, Reklamation)

Was passiert: Legt eine Aufgabe "Reklamation prüfen" im Projekt an. Zugewiesen an den Projektverantwortlichen (oder Sammelbearbeiter 270612).

M11: E-Mail Forward an reklamation@ (Route 1)

Was passiert: Die Original-Mail wird an reklamation@waerme-wimmer.de weitergeleitet, damit das Reklamationsteam sie auch direkt hat.

M12-M13: OpenAI Klassifizierung + Confidence-Router (Route 1 des Haupt-Routers)

Wann: Nur wenn Regex KEINE Projektnummer gefunden hat.

Was passiert: OpenAI bekommt den E-Mail-Text + eine Liste der letzten offenen Projekte für diesen Kunden. Beispiel-Antwort: "Projekt GRO-100042, Confidence 0.9" oder "NONE".

Wenn Confidence > 0.8: Weiter wie Route 0 (M4-M11). Wenn Confidence niedrig oder "NONE": Mail wird dem Fallback-Projekt "Eingang unsortiert" zugeordnet. Sabine/Michaela triagiert manuell. Keine Mail geht mehr verloren.

Error-Handler (M14)

Wann: OpenAI fällt aus, HERO ist nicht erreichbar, Netzwerkfehler.

Was passiert: Alert-Mail an monitoring@waerme-wimmer.de (WW-eigenes Postfach). Mail bleibt auf S3 gespeichert und kann nach der Fehlerbehebung erneut verarbeitet werden.

Vergleich zum IST: Im alten Szenario ging die Fehlermeldung an michael.klaus@hero-software.de (Michaels private Gmail). Das geht nach der Übernahme nicht mehr.

Zusammenfassung: IST vs. SOLL

Punkt IST (aktuell, 24 Module) SOLL (Rewrite, 14 Module)
Trigger Outlook-Polling alle 15 Min Mailgun-Webhook (sofort)
Nachts Deaktiviert (05:00-22:30) 24/7
Wenn Make ausfällt Mails stauen sich, gehen ggf. verloren Mails bleiben auf S3 erhalten
Projektzuordnung Nur Regex (trifft wenn Projektnr. im Betreff) Regex + KI-Fallback (Trefferquote nach Go-Live messen)
Unzuordenbare Mails Werden an info@ weitergeleitet + gelöscht Landen in "Eingang unsortiert" in HERO
Fehlermeldung An Michaels private Gmail An monitoring@waerme-wimmer.de
Anhänge Direkt aus Outlook Von S3 (archiviert + persistent)
Ops-Verbrauch ~34.000/Monat (Polling!) ~8.800/Monat (Event)
Calendar-Invite-Loop Bekannter Bug, ungefixt Mailgun filtert Calendar-Invites nativ
