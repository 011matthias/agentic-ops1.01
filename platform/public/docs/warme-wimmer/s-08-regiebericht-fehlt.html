SZENARIO 8 — REGIEBERICHT FEHLT ZU STATUSWECHSEL

Schedule: alle 420 min (7h), Mo-Fr 05:00-19:00
Auth: 3672 (Sabine)  |  Connection: 63756

Quell-Status:
  361036 = TG Termin bestaetigt
  368539 = NA Termin bestaetigt

Ziel-Status:
  361039 = TG Erledigt           368542 = NA Erledigt
  361037 = TG Regiebericht fehlt 368540 = NA Regiebericht fehlt

Hardcoded:
  document_type_id 1094611 = "Regiebericht" (oder "Reparatur-
       auftrag"? - mit Raphael verifizieren ob gleiche ID)
  category_id 254476 = Umsetzung
  category_id 254478 = Aushang notwendig

Mahn-Bedingung:
  formatDate(maturity_date) == formatDate(now)

Match-Bedingung:
  length(deduplicate(map(calendar_events.partners ueber Kategorie 254476/254478))) ==
  length(deduplicate(map(customer_documents.partner.id)))
  UND beide > 0

last 100 Limit -> bei mehr als 100 Projekten in diesen Status
werden weitere ignoriert.

BEKANNTE SCHWAECHEN:
- Mahn-Filter "maturity_date == today": faellt der Lauf an
  dem Tag aus, wird das Projekt NIE gemahnt (No-Self-Healing)
- Sleep 3s statisch -> bei API-Drosselung unzureichend
- Zwei GraphQL-Calls obwohl einer reichen wuerde
- last: 100 Limit ohne Pagination
- Kein Error-Handler
- Document-Type 1094611 ist potentiell sowohl "Regiebericht"
  als auch "Reparaturauftrag" (siehe Szenario 3) - Konflikt

GEPLANTE AENDERUNGEN IN N8N-MIGRATION:
- Mahn-Filter auf "maturity_date <= today" -> Self-Healing
- Pagination einbauen
- Document-Type-ID verifizieren mit Raphael, ggf. trennen
- Error-Handler + Alert
- Eine GraphQL-Query statt zwei
- Sleep variabel oder Rate-Limit-aware

Was tut es (Business-Outcome)

Schedule-Szenario. Lädt alle Projekte in Status "Termin bestätigt" (Step 361036 Tagesgeschäft + 368539 Nacharbeiten), max. 100.

Für jedes Projekt: lädt die Kalender-Events mit Kategorie "Umsetzung" oder "Aushang notwendig" (IDs 254476, 254478), zählt eindeutige Projektbeteiligte aus diesen Events, vergleicht mit Anzahl eindeutiger Regiebericht-Dokumente (document_type_id 1094611, nach partner_id dedupliziert).

  • Match (Anzahl Regiebericht = Anzahl Projektbeteiligte) → Projekt weiter auf nächsten Status (361039 / 368542)
  • Fälligkeit heute überschritten AND Anzahl Regiebericht < Anzahl Projektbeteiligte → Projekt auf Mahn-Status (361037 / 368540) = "Regiebericht fehlt"

Trigger

  • Typ: Schedule (Intervall nicht im Blueprint, setzen bei Import)

Branching-Logik

  1. HTTP-GraphQL (Auth 3672): project_matches(step_ids: [361036, 368539], last: 100) inkl. maturity_date, customer_documents(document_type_ids: 1094611), project_match_assignments
  2. BasicFeeder iteriert
  3. Sleep 3s
  4. HTTP-GraphQL (Auth 3672): Kalender-Events pro Projekt (redundant zur ersten Query, aber mit Kategorie-Namen)
  5. Router mit 2 Routen:
Route Filter Aktion
R0 Match Anzahl gleich AND Anzahl > 0 + step 361036 Status → 361039
R0 Match Anzahl gleich AND Anzahl > 0 + step 368539 Status → 368542
R1 Mahn maturity_date = heute AND Berichte < Beteiligte + step 361036 Status → 361037
R1 Mahn maturity_date = heute AND Berichte < Beteiligte + step 368539 Status → 368540
