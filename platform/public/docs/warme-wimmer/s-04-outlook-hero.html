1. Business-Outcome (was muss es tun)

Alle eingehenden E-Mails an info@waerme-wimmer.de werden automatisch:

  1. Einem Hero-Projekt zugeordnet (via Projektnummer im Betreff oder Body, mit Fallback auf KI-Klassifizierung)
  2. Als Logbucheintrag ins Projekt geschrieben (Absender, Betreff, Datum, OpenAI-Kurzzusammenfassung)
  3. Anhänge werden extrahiert und je nach Typ als Dokument oder Bild ins Projekt hochgeladen
  4. Bei Reklamations-Keywords wird automatisch eine Aufgabe im Projekt erzeugt und an reklamation@... forwarded
  5. Die E-Mail wird nach erfolgreicher Verarbeitung aus dem Info-Postfach entfernt (auf S3 archiviert)

Bei Fehlern (OpenAI-Ausfall, kein Projekt gefunden, Parsing-Error) wird eine Alert-Mail an eine WW-interne Monitoring-Adresse geschickt (nicht mehr an Micha's Gmail) und die E-Mail bleibt im Postfach zur manuellen Sichtung.

4. Komponenten im Detail

4.1 Mail-Ingest: Outlook-Forwarding → Mailgun

Entscheidung Meeting 2026-04-15: MX-Record bleibt bei Microsoft 365; Mailgun wird über Outlook-Weiterleitungsregel befüllt. Raphael: "Ich würde einfach eine Weiterleitung machen. Ich würde quasi eine andere Domain der Mailgun zur Verfügung stellen."

Setup: - Neue Subdomain: mg.waerme-wimmer.de (DNS MX bei Mailgun, DKIM/SPF bei Mailgun) - Mailgun-Route: match_recipient("ingest@mg.waerme-wimmer.de") → store + forward-to-webhook - Outlook-Server-Regel: "Eingehende Mail an info@ → Kopie an ingest@mg.waerme-wimmer.de behalten im info-Postfach bis Make bestätigt"

Vorteile: - Kein MX-Switch, andere W1-Automatisierungen unberührt - Event-getrieben, kein Polling — kein Postfach-Overflow, kein Zeitfenster-Problem - Mailgun hält Raw-Mails 3 Tage vor (Resend-Möglichkeit) - Kostenrahmen planbar (siehe Kostenkalkulation)

Risiken / offene Punkte: - Outlook-Server-Regel muss im M365-Admin-Center gesetzt werden (Raphael / Leonhard) - Kopie-Weiterleitung: Info-Postfach darf sich nicht mehr füllen → Archiv-Regel nach Make-Bestätigung nötig (Housekeeping-Szenario) - Fallback wenn Mailgun down ist: Mails sammeln sich im info-Postfach, werden nicht doppelt verarbeitet

4.2 Mail-Storage: S3

Entscheidung Meeting 2026-04-15: Raw-Mails + Attachments liegen auf S3, nicht mehr in Outlook. Raphael: "E-Mails sollen auf S3 gespeichert und von dort angezeigt werden."

Setup (mit Leonhard): - Bucket: ww-mail-archive (Region: eu-central-1 Frankfurt, DSGVO) - Lifecycle-Policy: Standard-Tier 180 Tage, dann Glacier - IAM-User für Mailgun: nur s3:PutObject auf raw/* - IAM-User für Make: s3:GetObject + s3:HeadObject für Presigned-URL-Generation

Keying-Schema:

raw/{YYYY}/{MM}/{DD}/{message-id}.eml
attachments/{YYYY}/{MM}/{DD}/{message-id}/{sha256}-{original-filename}

Leonhards Fragen (aus Meeting) beantwortet: - Was wird gespeichert: .eml-Raw + alle Attachments (PDFs, Bilder, Office-Docs) - Datenrelevanz: DSGVO-relevant (Kundenmails). Zugriff auf Mitarbeiter beschränken, Löschfrist klären (gesetzliche Aufbewahrungspflicht = 6 oder 10 Jahre). - Größe pro Jahr: ~100 GB (Schätzung WW, 2026-04-15). Budget-Basis für Backups.

4.3 Projekt-Matching: Regex + KI-Fallback

Ist-Zustand: Regex matcht Projekt-Nr in Subject/Body, bei Nicht-Match wird Mail als Fehler gehandelt.

Soll-Zustand (aus Meeting): Raphael: "Projektzuweisung auch KI-basiert noch mal verbessern, kann ich mir vorstellen. Können wir einfach mal drüber nachdenken."

2-stufiger Ansatz: 1. Regex first (Kosten = 0). Pattern: \b[A-Z]{3}-\d{3,6}\b (bestätigt per Klaus-PDF + Blueprint). Trifft nur, wenn Projektnummer im Betreff/Body steht. Trefferquote unbekannt (keine Messdaten aus HERO-Betrieb vorhanden, muss nach Go-Live gemessen werden). 2. OpenAI-Fallback wenn Regex leer ist. Prompt: "Extract the most likely Hero project number from this email. Return only the number or NONE. Context: recent open projects for this customer: [LIST]." gpt-4o-mini, ~200 tokens in + 10 out.

Bei Confidence-Score < 0.8 oder Antwort "NONE": landet in Fallback-Projekt "Eingang unsortiert" (muss Sabine/Michaela manuell triagieren). Kein stilles Dropping mehr.

4.4 OpenAI-Nutzung

Zwei Calls pro Mail (im Worst-Case): 1. Projekt-Klassifizierung (nur wenn Regex leer): ~210 tokens 2. Logbuch-Summary (immer): Prompt 800 tokens + Completion 150 tokens

Model: gpt-4o-mini (Input $0.15/M, Output $0.60/M)

Kosten pro Mail (Best/Avg/Worst): - Best (Regex trifft, Mail kurz): 1 Call a 800/150 = $0.00021 - Avg: $0.00035 - Worst (Regex leer + Mail lang): 2 Calls, $0.00085

Bei 50 Mails/Tag × 22 Werktage = 1100 Mails/Monat × $0.00035 = ~$0.40/Monat. Marginal. Siehe Kosten-Page für Gesamt-Budget.

WW-eigener Key erforderlich (offen: Raphael klärt ob WW OpenAI-Account hat).

4.5 Hero-Schreibpfad

Logbuch-Eintrag: - Endpoint: Hero native Modul app#herosoftwareintern-ba9lus:CreateProjectLogEntry (bevorzugt) oder GraphQL-Mutation via http:ActionSendDataAPIKeyAuth - Felder: project_id, type: email, sender, subject, summary, original_date, s3_url (Link zur .eml-Datei)

Attachment-Upload: - Bilder (jpg/png/heic): UploadImage-Modul - Dokumente (pdf/docx/xlsx): UploadDocument-Modul - Hero-API-Token: Sammelbearbeiter HERO (neu generiert durch Raphael via Self-Service) - TinyURL-Umweg entfällt (Hero-Subdomain-Bug behoben laut Meeting 2026-04-09)

Früher wurde hardcoded user_id 270612 (Sabine) verwendet — Raphael bestätigen.

4.6 Fehlerbehandlung & Monitoring

Alert-Ziel (neu): monitoring@waerme-wimmer.de (WW-eigenes Postfach, von Raphael anzulegen). Ersetzt michael.klaus@hero-software.de.

Drei Fehlerklassen: 1. Retriable (OpenAI-Timeout, Hero-5xx, Netzwerk): Make Error-Handler mit Exponential-Backoff, max 3 Versuche. 2. Permanent (Projekt nicht findbar, Attachment corrupted): Mail landet in "Eingang unsortiert", Alert informativ. 3. Fatal (Mailgun-Webhook-Signatur invalid, OpenAI-Kontingent leer): Alert + Scenario pausiert sich selbst, Rollback auf Outlook-Polling als Kurzfrist-Workaround.

Dashboard-Minimum: - Mails empfangen / verarbeitet / gefailed pro Tag (Make-Operation-Log) - OpenAI-Token-Verbrauch täglich (Usage-API) - S3-Bucket-Größe wöchentlich
