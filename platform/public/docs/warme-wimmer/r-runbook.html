Incident-Runbook

Was ist das? Ein Diagnose-Pfad für den Fall, dass eine Automatisierung kippt, mit Erst-Fix-Schritten und Eskalationspfaden. Wann brauchst du das? Wenn ein Szenario meldet "Fehler", die Operations-Quote überläuft, ein Webhook nicht reagiert, oder Outlook-Speicher knapp wird. Wer ist da, wenn du nicht weiterkommst? Siehe Kontakte und Eskalation. Erste Eskalations-Stufe ist immer Nico (UnpauseAI).

Erste 60 Sekunden: Wo schaue ich?

  1. Öffne das Dashboard. Dort siehst du:
  2. Make-Operations (Quote dieses Cycles)
  3. Aktive Szenarien (sollte 9/10 sein, W2-10 ist deferred)
  4. Outlook-Speicher (sollte unter 60% sein)
  5. Status-Tabelle mit allen 10 Szenarien
  6. Welche Zeile ist rot? Das ist dein Einstiegspunkt unten.

W2-01 Aufgabe erledigt, Webhook reagiert nicht

Symptom: Kein neuer Run in Make-History; Sabine meldet "Aufgabe erledigt aber nichts passiert".

Diagnose: 1. Öffne W2-01 Detail → Make-UI-Link. 2. Im Make-UI → Webhook-Modul → "Re-determine data structure" → eine Test-Aufgabe in Hero erledigen. 3. Wenn der Webhook keine Payload sieht: Hero-Custom-App-Webhook-Registrierung defekt. → Eskalation Hero-Support. 4. Wenn Webhook Payload sieht aber nichts passiert: Modul-Filter-Drift. → Filter prüfen, Lastenheft Cross-Reference.

Erst-Fix: Im Make-UI das Szenario manuell deaktivieren + reaktivieren. Triggert Webhook-Re-Sync.

W2-02..W2-09: Status "Fehler" auf Dashboard

Symptom: Eine S-XX-Zeile zeigt rotes "Fehler"-Badge.

Diagnose: 1. Öffne die Detail-Seite des Szenarios → Status-Card → Make-UI History Link öffnen. 2. Letzten Failed-Run anklicken. Was ist die Fehler-Meldung? - OAuth token expired → Connection erneuern. Im Make-UI → Connection → Re-authorize. - Hero API 4xx → Hero-API-Token raus. Prüfe .env MAKE_API_TOKEN_WARME_WIMMER. → Eskalation Raphael (Token-Owner). - Webhook timeout → Hero-Seite langsam. Erst beobachten (1-2 Cycles); wenn dauerhaft → Hero-Support. - OpenAI rate limit → tritt nur in W2-04 auf. → Modell-Swap prüfen (sollte gpt-5-mini sein, nicht 4o-mini).

Erst-Fix: Falls Sabine wartet: Test-Eintrag manuell durchschicken (Test-Konvention im Lastenheft). Wenn das durchgeht, ist das Live-Issue temporär.

W2-10: Status "deaktiviert"

Symptom: Dashboard zeigt W2-10 als deaktiviert.

Diagnose: Das ist gewollt. W2-10 ist deferred zur n8n-Migration wegen 50-Result-Hero-Pagination-Limit. Siehe Decision-Log m-04-25.

Erst-Fix: Nichts tun. Wenn ein Stakeholder fragt: "Migrationsentscheidung; wird in n8n neu gebaut, ETA nach Leonard-Setup."

Make-Operations 80%+: droht Quoten-Limit

Symptom: Dashboard-KPI-Bar wird gelb / rot.

Diagnose: 1. Im Make-UI → Organization → Usage → welcher Tag hat den Spike? 2. Welches Szenario ist verantwortlich? Top-Liste in der Make-UI. 3. Häufigster Verursacher: W2-04 Calendar-Invite-Loop (sollte nicht mehr auftreten, Regex wurde verschärft; siehe m-04-24). Falls doch: Loop muss sofort gestoppt werden.

Erst-Fix: - Kurz: Auto-Buy ist aktiv → kauft automatisch zusätzliche Operations bis +30%. Schaut Nico an. - Langfristig: Wenn Quote dauerhaft 90%+ → Tier-Upgrade Pro 80K. → Eskalation Raphael (Kosten-Frage).

Hero-Webhook reagiert nicht (W2-01 oder W2-05)

Symptom: Make-Side ist OK, aber Hero schickt keine Payload.

Diagnose: Bekanntes Hero-Bug-Muster. Bei JSON-Re-Import in Hero geht die Event-Auswahl verloren (W2-05 hatte das einmal). → Im Hero-UI prüfen: ist das Event "Projekt erstellt" wirklich aktiviert?

Erst-Fix: Webhook in Hero-UI neu registrieren mit korrektem Event. Kein Make-Side-Filter; der ist nicht das Problem.

Outlook-Speicher 75%+

Symptom: Dashboard-Outlook-Speicher-KPI wird gelb / rot.

Diagnose: 1. Schauen ob "Gelöschte Elemente" leer ist (Quick-Win 31% Speicher). 2. Wenn das nicht reicht: Upgrade 50 → 500 GB. Raphael hat zugestimmt, ist aber noch nicht ausgeführt (Stand 2026-05-06).

Erst-Fix: Sabine bittet, Gelöschte Elemente zu leeren. → 31% Speicher zurück.

Langfristiger Fix: Mailgun-Rewrite (Phase 2). Entkoppelt von Outlook-Speicher.

OpenAI-Modell aus / nicht erreichbar

Symptom: W2-04 wirft im Make-Log Fehler aus dem OpenAI-Modul.

Diagnose: 1. OpenAI-Status-Page öffnen. 2. Wenn Modell down: kein Make-Fix möglich. Warten.

Erst-Fix: Nichts tun außer warten. Wenn länger als 30 Min: kurz an Raphael melden, Auto-Buy kann durch wiederholtes Failover Operations fressen.

Mailgun-DSN-Bounce (Phase 2: noch nicht aktiv)

Status: Mailgun ist erst nach W2-04-Rewrite aktiv. Aktuell nicht in Betrieb. Eintrag bleibt als Platzhalter für Phase 2.

Zugang verloren / 2FA-Prompt

Symptom: Du kommst nicht in Make / Hero / Notion.

Eskalation: - Make-Login: Nico hat Master-Account (nicolas@unpauseai.com). Reset über Make selbst. - Hero-Login: Raphael ist Hero-Admin. - Notion: Wärme-Wimmer-Workspace, Irina kann einladen.
