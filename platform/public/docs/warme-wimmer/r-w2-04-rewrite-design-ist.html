Wie es funktioniert (einfach erklärt)

Alle 15 Minuten (Mo-Fr, 05:00-22:30) passiert Folgendes:

Make fragt Outlook: "Neue Mails im Postfach hero.automation@?"
    │
    │  Für JEDE gefundene Mail (bis 200 pro Lauf):
    │
    ├── Schritt 1: Betreff + Vorschau nach Projektnummer durchsuchen
    │              (z.B. "HUK-100040" per Regex-Muster)
    │
    ├── Projektnummer gefunden?
    │       │
    │       ├── JA → Projekt in HERO nachschlagen
    │       │       │
    │       │       │  Dann passieren 3 Dinge GLEICHZEITIG (parallel):
    │       │       │
    │       │       ├── 1) ANHÄNGE verarbeiten (wenn vorhanden)
    │       │       │      Bilder (PNG/JPG) → HERO Bildergalerie
    │       │       │      Dokumente (PDF etc) → HERO Ordner "Allgemein"
    │       │       │
    │       │       ├── 2) HAUPTPFAD:
    │       │       │      OpenAI fasst Mail zusammen (GPT-4o-mini)
    │       │       │      TinyURL kürzt den Outlook-Weblink
    │       │       │      Logbuch-Eintrag in HERO schreiben
    │       │       │      │
    │       │       │      └── Ist Projekt in "Reklamation"-Status?
    │       │       │              JA → Forward an reklamation@
    │       │       │              NEIN → Task "Neue Mail lesen" anlegen
    │       │       │
    │       │       └── 3) AUFRÄUMEN: Mail aus Postfach löschen
    │       │
    │       └── NEIN (keine Projektnummer gefunden)
    │               → Mail weiterleiten an info@waerme-wimmer.de
    │               → 5 Sekunden warten
    │               → Mail aus Postfach löschen
    │
    └── (nächste Mail)

Was tut es (Ist-Zustand, technisch)

Das zentrale E-Mail-Ingestion-Szenario. Pollt alle 200 Nachrichten aus einem definierten Outlook-Folder des M365-Accounts (Connection 61784 = Hero-Automation-Postfach). Für jede Mail:

  1. Extrahiert Projektnummer aus Subject + Body-Preview per REGEX
  2. Schlägt Projekt in HERO nach
  3. Wenn Projekt gefunden:
  4. Lädt Attachments hoch (PDF → Dokument, Bilder → Image-Kategorie "Bilder vom Kunden")
  5. Erzeugt Logbuch-Eintrag mit OpenAI-zusammengefasstem Mail-Body und TinyURL-Kurzlink zum Outlook-Webmail
  6. Legt ggf. Task "Neue Mail lesen" an
  7. Leitet an reklamation@waerme-wimmer.de weiter wenn Projekt in Reklamationsstatus
  8. Löscht Mail
  9. Wenn keine Projektnummer oder kein Treffer → Mail nach info@waerme-wimmer.de weiterleiten + löschen

Trigger (Ist)

  • Typ: Event (Polling) -- microsoft-email:watchMessages, 200 Nachrichten/Lauf
  • Outlook-Folder-ID: AAMkADNjN2RhODU1LWY5ZTctNGY4Ni05YTdjLThiOTVhNjZiYmMzMAAuAAAAAAA1yqiQerSkSrXEslY7-RemAQAAUROkpOoTTJCfHJMHL4ZRAAAAAAEMAAA=
  • Connection: 61784 (azure/Outlook, Hero-Automation-Postfach)
  • Abgerufene Felder: body, bodyPreview, from, hasAttachments, subject, webLink

REGEX-Projektnummer-Matching (Modul 3)

  • Pattern: \b[A-Z]{3}-\d{3,6}\b (drei Großbuchstaben, Bindestrich, 3–6 Ziffern)
  • Input: {{1.subject}} {{1.bodyPreview}} (subject + preview concat)
  • Flags: global: True, sensitive: False, continueWhenNoRes: True
  • Downstream nutzt nur last(split(__IMTMATCH__; "-")) -- nimmt die Zahlen nach dem Bindestrich als relative_id für project_matches(relative_id: ...)

Branching-Logik (Ist, detailliert)

Top-Router:

  • Route A -- "Projektnummer gefunden" (Filter: __IMTMATCH__ exists AND i = 1 -- genau 1 Regex-Match):
  • GraphQL-Call (Auth 3785) project_matches(relative_id: ...) -- lädt Projekt-Details + Status + Partner
  • Sub-Router mit 3 Unter-Routen:
    • A1 -- "Has Attachments": listAttachments → downloadAnAttachment → Sub-Router:
    • Nicht-Bild → hero-software:UploadDocument (conn 63384, document_type_id 688384, document_folder_id 654644)
    • Bild → hero-software:UploadImage (conn 63384, category "Bilder vom Kunden")
    • A2 -- Haupt-Pfad:
    • OpenAI CreateCompletion (conn 62622, gpt-4o-mini, top_p=1, max_tokens=2048, temp=1)
      • Prompt: "Entferne die Signatur und fasse die Mail zusammen. Entferne alles an HTML und fuege ausschließlich <br> für Zeilenumbruche hinzu. Email: {{1.body.content}}"
    • TinyURL-Call (Auth 3732) -- kürzt Outlook-Webmail-Link
    • Logbuch-Eintrag (hero-software:createLogbookEntry, conn 63384): target=project_match, Text = <a href="TinyURL">E-Mail</a> von {{from.name}} ({{from.address}}) vom {{createdDateTime}}: <br><br>{{"Anhänge vorhanden" wenn hasAttachments}}<br><br>{{OpenAI summary}}, role_visibility=[branch_manager, worker, accounting, sales]
    • Sub-Router:
      • "Keine Reklamation" (step.name ≠ "Reklamation"): GraphQL tasks(project_match_id, is_done: false) → wenn kein Task mit Titel "Neue Mail lesen" existiert, update_task anlegen für target_user_id: partner.user_id mit due_date +1 Tag
      • "Reklamation" (step.name contains "Reklamation"): microsoft-email:forwardMessage → reklamation@waerme-wimmer.de
      • unconditional: microsoft-email:deleteAMessage
    • A3 -- "Keine Projekt → Weiterleitung" (project_matches = 0 OR REGEX ≠ project_nr): forward an info@ → Sleep 5s → delete
  • Route B -- "Keine Projektnummer gefunden" (__IMTMATCH__ notexist): forward an info@ → Sleep 5s → delete

Delete-Logik (Ist)

  • Jede Terminal-Route endet mit microsoft-email:deleteAMessage (Modul 34, 35, 36)
  • Sleep 5s (util:FunctionSleep) vor Delete bei Forward-Zweigen, Zweck: Forward-Zustellung abwarten bevor Original gelöscht wird
  • Delete vor Verarbeitungsbestätigung -- wenn Hero-Upload fehlschlägt, aber Forward erfolgreich war, ist Mail weg
