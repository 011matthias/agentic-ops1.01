Annotations

SZENARIO 5 — PROJEKT ERSTELLT

Trigger: hero-software:WatchProjects (alte Hero-App)
Webhook-ID: 55349  |  Auth: 3672 (Sabine personalisiert)
Connection: 63384

Drei parallele Routen, keine sind Mutex:
  R0: Logbook mit partner_notes  (Filter: notes exists)
  R1: Logbook mit Osneo-URL       (kein Filter, IMMER aktiv)
  R2: UpdateProject mit Notes     (Filter: notes ODER addr exists)

Hardcoded:
  Osneo-Subdomain: waerme-wimmer.osneo.de/documents/{display_id}

BEKANNTE SCHWAECHEN:
- R1 hat keinen Filter -> Logbook-Eintrag mit kaputtem Link
  wenn display_id leer ist
- Osneo-Subdomain hardcoded -> bei Domain-Aenderung bricht alles
- Auth 3672 ist Sabines persoenlicher Token. Bei Sabine-Ausfall
  bricht das Szenario.
- WatchProjects feuert auch bei Status-Wechseln, nicht nur bei
  Erstellung (Hero unterscheidet das nicht im Webhook-Event).
  Daher laufen Logbook-Eintraege mehrfach pro Projekt.

GEPLANTE AENDERUNGEN IN N8N-MIGRATION:
- R1 Filter einbauen: nur wenn display_id exists
- Osneo-Subdomain als Konfig-Variable (Umgebungs-Variable)
- Auth auf service-artigen Token (Sammelbearbeiter 3785)
- Trigger-Event-Filter: nur "Projekt neu angelegt", nicht
  jeder Status-Wechsel

Was tut es (Business-Outcome)

Wenn in HERO ein neues Projekt angelegt wird, erzeugt dieses Szenario:

  1. Einen Logbuch-Eintrag mit den Kunden-Notizen aus dem Kontakt-Datensatz
  2. Einen Logbuch-Eintrag mit einem Link auf die Dokumente-Seite der Osneo-Subdomain
  3. Kopiert Kontakt-Notizen + Adress-Beschreibung in die Projektnotizen

Damit stehen relevante Kundeninfos direkt im Projekt sichtbar.

Trigger

  • Typ: Event (hero-software:WatchProjects, alte Variante)
  • Hook-ID: 55349

Branching-Logik

Zwei sequentielle GraphQL-Queries (Auth 3672 = Sabine):

  1. Query 1: project_matches(ids: {{1.id}}) lädt contact.partner_notes, address.customer_address.id, partner_notes
  2. Query 2: contacts(ids: {{1.customer.id}}) lädt customer_addresses[].description

Dann Router mit 3 Routen (keine Exklusiv-Filter — jede läuft unabhängig):

Route Filter Aktion
R0 contact.partner_notes exists Logbuch-Eintrag mit partner_notes
R1 immer Logbuch-Eintrag mit Osneo-URL
R2 partner_notes.length > 0 OR address.description.length > 0 UpdateProject(partner_notes)
