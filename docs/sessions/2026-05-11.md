**Friction events:**

1. **PDF toolchain dependency hell on first build.** `xhtml2pdf>=0.2.17` pulled `python-bidi>=0.6` which requires Rust on Windows. Pinning to `0.2.13` hit a `ShowBoundaryValue` import mismatch with reportlab 4.x. Pivoted to `fpdf2`. Latin-1 limitation on the built-in Helvetica then crashed on the `•` bullet character. Added Unicode TTF auto-detection. Then hit a `self.font_family` attribute collision with the parent FPDF class — renamed to `body_family`. ~45 minutes of friction before working build. (User later rewrote the tool entirely to Edge headless, which avoids all of this.)
2. **Hook-induced regeneration cycle.** Each user-driven content edit to `instantly-audit2.md` triggered three separate hook acknowledgments: PreToolUse Reference Anchor Check on Edit, iteration-3x gate-skip on the Bash regen, B1 stop hook on the brief completion message. ~15 edits × 3 hooks = ~45 acknowledgment cycles. The iteration-3x hook in particular fired on benign user-driven iteration, not on a fix-then-test failure loop. Operationalization suggested: a `--watch` flag on `md-to-pdf.py` to auto-regenerate on file change, removing the explicit Bash invocation per edit.
